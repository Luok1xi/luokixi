# 移动端与同步：密码只在手机，服务器只存数据

参照 [thu-info-app](https://github.com/thu-info-community/thu-info-app)。它能帮同学查图书馆、约座，关键不在于"爬学校系统"，而在于**密码从不离开同学自己的手机**。我们照这条做。

## 角色分工

| 端 | 做什么 | 碰不碰学校密码 |
|---|---|---|
| **手机 App**（独立仓库，不在本仓库） | 同学在 App 里输入学校统一认证账号，密码存进手机系统钥匙串（iOS Keychain / Android Keystore）。App **直接**和学校系统通信：查图书馆余座、约座、查成绩、校园卡、课表。约座等操作是同学本人在自己手机上、用自己的账号完成的。 | 碰。只在本机，直连学校，不经过任何服务器。 |
| **Luokixi 服务器**（本仓库 campus/hub） | 只做两件事：① 存同学**选择同步**上来的数据（余座记录、成绩、课表……），按账号隔离，只有本人能读；② 资料库、校圈、开源广场等公开内容。 | **永不碰。** 不接收、不转发、不代为登录。 |
| **网站 / 电脑端**（本仓库） | 同学登录 **Luokixi 账号**（不是学校账号），看手机已经同步上来的数据；资料库照常用。 | 不碰。电脑端没有学校登录入口。 |

数据流向永远是 **手机 → 学校**（取数据）和 **手机 → Luokixi 账号 → 电脑**（同步展示）。绝不会出现 **电脑/服务器 → 学校**。

## 为什么这样就安全

- 全校同学的学校密码不会集中到一台服务器上，所以不存在"一处被攻破、全校账号泄露"。每个人的密码只在自己手机里。
- 代替登录、代为约座发生在同学**本人的设备**上、用**本人的账号**，这是同学为自己操作，等同于自己打开 App 点一下。
- 服务器上存的是同学本人的数据（成绩、校园卡属于个人敏感信息），按账号严格隔离、仅本人可读，并且**按类型逐项选择是否同步**，不默认全量上传。

## 同步接口（本仓库已实现，不涉及密码）

手机取到数据后，带着同学的 **Luokixi 登录态**把数据推上来；服务器只存不问来源是怎么登录的。

- `POST /api/hub/sync/push` — body `{kind, data, source?, fetchedAt?}`。`kind` 限 `seat`/`grades`/`card`/`timetable`/`library`/`exam`。`data` 是 App 已经整理好的 JSON（有大小上限）。覆盖同一 `kind` 的上一次同步。
- `GET /api/hub/sync` — 返回本人全部已同步数据，供电脑端展示。
- `POST /api/hub/sync/clear` — body `{kind}` 或 `{kind:'all'}`，删除本人的同步数据。

都要求登录（Luokixi 账号 + CSRF），且只能读写自己的；请求与响应都 `private, no-store`。**服务器不接收任何学校账号或密码字段**——`push` 里带了密码之类的字段会被忽略/拒绝。

## 待学校授权才做的（更稳妥的正路）

如果学校愿意给**统一身份认证 OAuth**，App 就能走学校自己的登录页授权，连 App 本机都不用存密码；余座这类接口也能直接官方对接。这条要学校信息化部门开通，和上面的本机方案不冲突，可以之后叠加。
