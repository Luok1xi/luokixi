# 首页动画与新闻配图修正 · v0.3.1

Owner 反馈首页动画仍卡顿，并明确图片指首页大新闻配图。

## 原因与修正

| Before | After | Why |
|---|---|---|
| 弹簧按帧递推，最多只记 32ms 经过时间 | 按真实时间求弹簧解析解，一次生成关键帧，浏览器播放 transform / opacity | 慢帧不再拖慢动画时间；主线程不逐帧改卡片样式 |
| 逐帧改层级、可见性、空媒体层位置 | 层级与可见性仅在动作边界或拖动跨卡时更新；取消空媒体视差 | 减少样式写入与无效合成层 |
| 进度点动画修改宽度，大卡按钮实时背景模糊 | 固定进度点宽度，移动卡片按钮用固定透明材质 | 消除反复重排与背景采样 |
| 开场退出与第二次整屏入场重叠 | 保留首次开场，结束后直接呈现已渲染首页 | 避免两层大面积同时变换与透明混合 |
| 新闻详情用 View Transition 快照，入场时真实关闭控件无法命中 | 真实 DOM 上做可中断 FLIP，关闭控件保持可点击 | 不再让用户等待开场才能关闭 |
| 国庆新闻只有底色 | 原报道第 2 张升旗现场照片，桌面与手机保留国旗主体 | 真实事件采用对应报道照片；没有替换成虚构现场 |

连续点击从当前动画位置和速度继续；拖动取消、缩放、后台、返回缓存页面、减少动态效果均清理拖动状态。自动轮播在详情页打开或离屏时暂停。鼠标按住拖动后离页不会产生意外点击。

## 性能对照

同一本机 Edge、1440 × 1000 / 390 × 844、2 倍像素密度、4 倍 CPU 减速，加载稳定后连续切换 3 张。两组性能对照均在新闻配图接入之前完成，以相同内容比较动画实现。数据是浏览器跟踪，不是实体手机或用户当前内嵌浏览器的 FPS 承诺。

| 指标 | 桌面修改前 → 后 | 手机视口修改前 → 后 |
|---|---|---|
| 行内样式写入 | 5250 → 55 | 5658 → 55 |
| Layout 次数 | 315 → 6 | 351 → 6 |
| Paint 次数 | 1184 → 57 | 1344 → 55 |
| 主线程任务累计 ms | 1744 → 645 | 1729 → 675 |

单次 spring 完成时间仍约 660ms，保留原本的空间翻转；目标是减轻每帧工作并消除掉帧时额外拖长，不用删除动效掩盖卡顿。

验证：5 项弹簧测试覆盖不同帧率相同时间、初末状态、反向连续、有限值和时限；浏览器检查快速反向、拖动、生命周期恢复、开场仅一次、减少动态效果、详情入场立即关闭与再次打开。其他业务接口没有修改，已有 73 项后端结果属于 v0.3，本次不重复宣称重跑。
