核验日期：2026-10-07（Asia/Shanghai）。对象：中国矿业大学（北京），`cumtb.edu.cn`。仅查看官方公开页面与未登录入口，没有提交学校账号、密码、验证码，也没有读取个人教务记录或私有会话。

## 官方核验结果

学校提供统一身份认证、教务系统和网上办事大厅。2025 级新生指南明确列出统一认证入口 [https://sso.cumtb.edu.cn/login](https://sso.cumtb.edu.cn/login)，可用于学校教务、学工、研究生、VPN 等服务；应由本人在学校页面完成登录。[新生信息化服务指南，2025-08-25](https://info.cumtb.edu.cn/info/1016/3007.htm)

截至本次核验，在学校公开页面中**没有查到面向第三方开发者的 OAuth/OIDC 客户端注册、授权 scope、回调地址登记或个人课表 API 文档**。这说明本轮没有足够依据实现 Luokixi 的学校授权接入，不能据此断言校内不存在 OAuth 或其他协议。登录页出现认证提供方名称，也不能证明 Luokixi 已获得接口权限。

已确认的接入路径是机构审批：网络与信息中心业务办理页要求拟接入统一认证的新系统填写应用系统接入审批备案表。该页面没有给出公众自助注册流程或可直接使用的客户端参数。[官方业务办理页，页面未标发布日期](https://info.cumtb.edu.cn/ye_wu_ban/2.htm)

学校信息化项目管理办法介绍了校内项目与统一数据交换平台、统一身份认证对接的原则；其适用范围包括使用学校信息化建设经费的项目。这是校内集成背景，不能直接推定私人应用有权调用接口。[信息化项目管理办法（试行），2022-06-15](https://info.cumtb.edu.cn/info/1003/2140.htm)

教务处 2026-03-12 的选课通知给出本人进入教务系统的路径：教务处官网 → 教务 WEB 系统 → 本科教学管理与服务平台 → 学生登录口。通知提到“我的课表”查询，但没有证明个人课表支持 CSV/ICS 导出。公开课程安排附件也不等同于个人选课结果。[官方选课通知，2026-03-12](https://jwc.cumtb.edu.cn/info/1133/5895.htm)

## 当前可用的本地方案

1. 在[学校教务处](https://jwc.cumtb.edu.cn/)或[学校统一认证](https://sso.cumtb.edu.cn/login)页面由本人核对课表。学校如果提供导出，下载本人文件后选择导入；本次未确认该导出功能。
2. 没有导出时，可以复制可见的表格文字，或使用 CSV 模板自行整理。填写星期/日期、实际开始和结束时间、周次、单双周、地点等。只有“第 1–2 节”而没有明确时间的数据必须补齐；模板里的时间和日期只是示例，不代表矿大作息。
3. 先解析预览，核对数量、日期、时间、地点和全部警告。课程楼名不会被猜成地图上的建筑，预览保留文字教室，地图关联可由用户之后选择。
4. 确认预览后由页面整体验证与合并。解析模块不读取或改写本机已有计划，失败时没有部分写入。学校账号和日程文件无需交给服务器或 AI。

## 模块接口

实现文件：`src/js/campus-import.js`。只依赖现有 `fflate` 和 `campus-plan.js` 归一化规则，不新增运行时依赖。

```js
import { parseCampusImport, parseCampusText, sampleCSV } from './campus-import.js';

const term = { label: '我的学期', starts: '2026-09-07', weeks: 20 };
const preview = await parseCampusImport(file, { term });
// preview: { courses, events, warnings }

const pasted = parseCampusText(text, {
  term,
  columnMap: { title: '学科', start: '从几点', end: '到几点' },
});
const template = sampleCSV();
```

`term.starts` 是第 1 周的周一，允许留空；`weeks` 是 1–30 的整数。不设学期开始日期仍可预览有星期的课程，但会提示课程实际日期和日历导出需要学期信息。个人单次日程不需要虚构学期。

`columnMap` 的键是标准字段名，值可以是源表头文字或从 0 开始的列索引。可映射 `title/id/kind/courseId/weekday/date/start/end/weeks/weekMode/room/location/teacher/notes/repeat/until/color/floor/participants/sourceURL/registrationURL/projectURL`。可选 `format` 为 `ics/json/table/csv/tsv/text`，`delimiter` 为逗号、制表符、分号或竖线。多工作表 XLSX 必须明确选择或另存单表，接口可传 `sheetName`。

输出只有规范化的课程、日程和警告。页面负责合并后再次调用完整计划校验、处理既有 ID 冲突并等待用户确认；模块本身不写 localStorage、IndexedDB、云端 planner、外部日历或任何账户，也不发网络请求。

## 格式与明确边界

| 格式 | 已实现 | 无法确认时的处理 |
| --- | --- | --- |
| CSV / TSV / 表格文字 | 中英文表头、表头映射、引号与换行备注、具体起止时间、星期、日期、课程周次、单双周、同课程多时段、课程教师与教室、个人/考试等日程 | 缺具体时间、错误日期、未知日程类型、破损引号拒绝整个预览；未知列给警告；同课程重复时段提示只保留一次 |
| JSON | 规范化的 `courses`、`events` 列表，完整源数据校验，支持当前校园中心字段 | 密码或登录令牌字段拒绝；非法内容拒绝。导入只合并课程/日程，个人资料、到访记录、隐藏安排、显示设置等不会覆盖，并给出警告；完整备份恢复应走独立流程 |
| ICS | iCalendar 2.0 单次事件、每周 RRULE、INTERVAL/COUNT/UNTIL/BYDAY、EXDATE、UTF-8 折行与文字转义、UTC 和 Asia/Shanghai | 每周规则先展开为具体日期的单次事件；浮动时间明确警告按北京时间解释；无限每周规则必须有已选学期并提示边界。复杂频率/筛选、RDATE/EXRULE/RECURRENCE-ID、取消版本、全天/跨午夜/非零秒或其他时区拒绝，不静默改写 |
| XLSX | 现有 fflate 流式解压、内联/共享文字、明确数字时间、1900/1904 日期系统、指定工作表 | 旧 XLS、公式单元格、宏路径、外部关系、DTD/实体、异常结构/压缩体积拒绝；不执行公式或使用公式缓存。文字始终按文字读取 |

ICS 附件、参与人邮箱、组织者账户和嵌套提醒不会导入，页面会得到警告。导入后提醒由本地计划设置决定。ICS 已支持的每周规则必须能在最多 730 天内完整展开；超量拒绝。提醒和地点不因无法确认而补造。

CSV、TSV、TXT、ICS、JSON 文件必须为有效 UTF-8；CSV 模板带 UTF-8 BOM。XLSX 读取的是文件内单元格值，其格式、图片和附件不会成为计划数据。

## 资源限制与验证

文件最大 5 MB；XLSX 总展开最大 16 MB、单文件展开最大 4 MB、最多 128 个压缩条目，较大条目展开比例最大 200 倍。表格最多 2000 行、64 列、20000 个单元格；XML 限定层数、节点数及合法实体，不允许外部实体或外部关系。

最终课程最多 60 门，每门最多 14 个时段，日程最多 500 项。日期、时间、周次、URL、文字长度和唯一 ID 继续由 `campus-plan.js` 的严格规则验证。所有数量限制触发错误，不截断后保存。
