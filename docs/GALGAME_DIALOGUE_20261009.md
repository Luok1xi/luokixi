# Galgame 对话与上下文优化（2026-10-09）

Owner 本轮要求：在现有北矿娘 / Codex / 双人工作室上使用游戏式点击推进、语音打断、已读历史、漫符和人物微动，并优化长对话与工具调用。没有新建替代角色。

## 已接入当前本机站点

- 默认手动推进。点击对白或「继续」立即停止当前声音、推进一条模型原有消息并播放其日语台词；合成尚未完成时也可推进，迟到的音频不会覆盖新句。Enter / 空格可推进。
- 自动推进改为可选开关。有声音时等声音结束；关闭声音时按阅读时长推进。
- 「对话历史」只收录已读句子；上一句、打开历史、关闭历史、刷新页面不会自动重播。「重听」明确触发当前句朗读。完整原聊天列表仍保留。
- 直接复用 Owner `E:/Lv/game/js/engine/sprites.js` 的漫符 SVG；保留游戏纸页、胶带和字体，使用游戏呼吸微动幅度。按当前消息的情绪切换立绘与漫符，讲话、思考和待机动作分开。页签隐藏、舞台离屏或收起会停止声音与持续运动。
- 减少动态效果时保留静态表情符号，关闭位移和逐字动画。游戏源文件未改。

## 长对话和执行器

- 两位角色共用 `ConversationContext` 代码，各自数据库、摘要、人格与长期记忆仍独立。
- 未压缩消息达到 32 条或正文达到 18,000 字符后，在当前回复结束后后台整理。保留最近 12 条完整上下文；前面的整段合并为一份持续更新的摘要。过长输入按连续批次合并，不截断后冒充已总结。
- 旧聊天原文不删除，取消原来的 200 条自动裁剪。提供可发现的 `conversation_history` 只读工具，按词或消息编号回查原文。
- 摘要成功后才推进游标；失败或额度不足会延后，清除历史会使在途摘要失效。摘要不能更新人格、制造授权或把计划写成执行回执。保留原预算约束。
- 维护执行器中，连续且互不依赖的只读工具最多 4 个并行；写操作仍是顺序屏障。重复读取复用真实结果，修改后作废读取缓存；动态任务状态允许有限刷新，写入不重复执行。
- 维护任务使用面向执行、回执和阻塞的提示，不再要求输出研究论文章节；代码操作仍保留深度检查。
