# 私有全站备份与隔离恢复验证

此工具用于保护本站账号、资料和社区记录。备份与恢复检查在本机完成；恢复默认生成全新目录，不会覆盖正在使用的数据库。

## 备份范围

- `hub/community.sqlite3`：全量社区数据库，包括账号及密码哈希、帖子、回复、草稿、上传署名、审核历史、收藏、关注、通知、项目、任务和工作室记录。SQLite 使用原生 backup API 获取一致性副本，支持原库服务继续运行和 WAL 模式。
- `hub/uploads/`：全部正式上传原件、预览图、项目镜像。按数据库中每一条 Asset 与 MirrorAsset 校验文件大小和 SHA-256；没有 Upload 署名记录的 Asset 也不会遗漏。
- `hub/secret.key`：Django 签名密钥，用于恢复既有会话和签名数据。即使生产配置通过环境变量提供此密钥，也只在私有备份内部保存，不输出内容。密码哈希也在私有数据库中。
- `library/library.sqlite3` 与 `library/files/`：可选旧资料库、检索、审核和上传数据及原件。旧库实际引用在其他本地文件夹的 PDF、MP3 等资料也逐项收集；只在副本中把绝对路径转换成备份内部路径。生产资料库不作修改。
- `public/files/`：可选的校内资料原件。这些文件仍是私有备份，不会因进入备份而公开。

**不包含源码、模型配置、API 密钥、学校登录凭据配置、邮件预览、临时下载和锁文件。** 恢复后的 AI 与邮件服务需要从独立的私有配置重新接入，不从备份包读取提供商密钥。源码由 Git 版本管理；清单记录数据库 schema 哈希、迁移版本、各表记录数、文件大小和 SHA-256。

## 存储与访问

Windows 默认位置是当前用户 `AppData/Local/Luokixi/backups`；其他系统默认 `~/.local/share/Luokixi/backups`。可用 `HUB_BACKUP_DIR` 指定源码目录、生产数据目录和网页公开目录以外的私有位置。

禁止把备份放在仓库、`public`、`dist`、Django static/media 目录内；禁止符号链接和 Windows 目录联接。备份含私人账号及文件，继承用户私有目录的系统访问权限；不提交 Git，不在静态网页提供下载。网页入口需由最高权限站主授权，并通过服务端受保护下载接口返回。下载使用已打开并验证的同一文件句柄，不在验证后重新打开用户可替换的路径。

每个备份由严格格式的编号标识，例如 `luokixi-backup-20261007T043819Z-6328f263f951.zip`。创建使用私有临时目录，先验证数据库、附件和打包后完整校验，再原子改名；错误不会生成可用备份条目。操作锁防止并发创建、检查和历史删除。

默认保留最近 7 份本工具生成的有效备份，每日一次时对应约一周；保留数可配置为 1–365。只删除本工具命名且清单格式有效的历史包及对应验证回执，其他文件保持原状。隔离恢复目录不会随保留策略自动删除，便于人工核对；需要清理时仅清理选定的 `restore-checks/<verificationId>`，不能删除整个备份目录。

## 命令

在项目根目录运行，使用已安装 Django 的 Python 环境。

```powershell
python campus/manage_hub.py hub_backup
python campus/manage_hub.py hub_backup --list
python campus/manage_hub.py hub_backup --retain 14
python campus/manage_hub.py hub_backup --no-library --no-public-files
python campus/manage_hub.py hub_restore_check "luokixi-backup-日期-编号.zip"
```

如需指定路径，在 PowerShell 设置 `$env:HUB_BACKUP_DIR='私有目录绝对路径'`。`--destination` 只允许尚不存在的私有目录；指定已存在目录或生产目录会直接拒绝。命令输出备份及隔离目录位置、清单摘要、验证结果，不输出密钥和用户内容。

恢复检查先校验 ZIP 路径、重复和大小写冲突、范围、容量、压缩比、每个条目大小及 SHA-256；再校验 SQLite 完整性、schema、迁移与表记录数，并核对所有数据库附件引用。ZIP 不接受未声明条目、目录条目、符号链接、加密条目或缺失账号库/签名密钥。默认最多展开 8 GiB、100,000 个文件；可设置 `HUB_BACKUP_MAX_BYTES`，仍有硬上限。工具自产包使用不压缩 ZIP，避免压缩峰值和异常压缩比。

校验成功的包恢复到 `backups/restore-checks/<verificationId>/`，账号库在其中的 `hub/`，旧库在 `library/`。旧库文件引用改到该隔离目录，并保留来源/审核等其他数据。网页只返回验证编号和统计，不暴露完整私有路径。验证回执包含整包 SHA-256；列表只有回执编号和当前包 SHA-256 同时一致才标记为已验证。

管理面板首次读取验证状态时校验整包，后续请求只有在包和回执的大小、纳秒修改时间均未变化时复用进程内结果。任何变化重新校验；下载和恢复检查始终执行完整校验，避免状态轮询反复读取所有大文件导致页面卡顿。

## 隔离试用与真正恢复

可把 `HUB_DATA_DIR` 指向隔离恢复目录内的 `hub`，`CAMPUS_DATA_DIR` 指向 `library`，在另一个端口启动只供自己访问的测试后端。停用维护、镜像、模型和预约后台任务；不要启动旧工作队列。旧库与 `public/files` 有原件，但现有前台是否使用该目录需要按部署方式调整。

真正恢复生产前，先在隔离环境确认账号能登录、帖子和审核历史正确、附件可下载、资料索引及原件可读，并确认源码兼容清单中的迁移版本。随后在单独安排的恢复操作中停止生产后端和工作进程，为当前生产数据再留一份备份，再把确认好的隔离数据接入生产配置。此工具不会自动执行覆盖或切换，不能把恢复检查当作生产恢复已完成。

## 后端接口约定

`hub.backup` 提供：

| 函数 | 行为 |
| --- | --- |
| `status()` | 备份清单、最新包、最近有效恢复验证、默认保留数、自动备份开关。 |
| `list_backups()` | 包编号、日期、大小、文件数、范围、每份真实验证状态。 |
| `create_backup(include_library=True, include_public_files=True, retain=7)` | 创建备份；建议工作队列执行，HTTP 只负责入队。 |
| `check_backup(backup_id)` | 隔离恢复及校验，返回可序列化摘要与验证编号；建议工作队列执行。 |
| `open_backup_file(backup_id)` | 站主授权后调用，返回已打开且校验过的句柄；由 `FileResponse` 负责关闭。 |
| `get_backup_path(backup_id)` | 严格编号及完整校验的路径工具；下载优先用上一项。 |
| `restore_backup(backup_id, destination=None)` | 命令工具调用，返回 `(结果, 私有隔离目录)`。 |

失败抛出 `BackupError`，说明不包含凭据值。API 必须验证用户权限、CSRF 和请求字段；用户不能通过 JSON 请求指定磁盘目录或秘密文件。`HUB_BACKUP_AUTO=1` 仅表示允许后台每日调度，由已有工作系统实现；模块导入与普通请求不会自行启动定时任务。
