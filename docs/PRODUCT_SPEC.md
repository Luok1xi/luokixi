# Luokixi 统一模块规格

版本：2026-10-06 / 六板块功能细化 v2.1。Owner 已确认六个一级板块、首页“编辑精选为主，搭配个人关注更新”、开源广场“项目推荐为主，学术前沿可单独切换”，并要求 Opus 开始页面工作、Codex 继续完善设计。第 13 节细化流程、字段和验收；新增字段、等级数值仍是待实施方案，不表示接口已提供。本轮 Codex 仅完善功能设计，不改业务代码或页面。

本文件统一管理产品范围、模块关系和验收效果；接口文档说明已经实现的接口，看板安排任务，交接文件记录变化。历史交接中的功能清单不再作为另一套路线图。最新用户指示优先于所有文档。布局、页面呈现与动画由 Opus 决定；Codex 负责业务逻辑、接口、数据、权限和测试。本轮不制作图片，素材交付另按协作记录排期。

## 1. 网站到底帮助同学完成什么

帮助矿大同学选择课程与资源、发现可用工具、参与创作，并积累真实成果。核心路径固定为：

**发现一个有用的创意 → 看懂项目、判断适不适合自己 → 找到正确入口和操作步骤 → 尝试或加入协作 → 展示成果、留下可追溯贡献。**

校园生活、口碑、科研和竞赛围绕这条路径互相连接。学习功能定位为引导：告诉同学学什么、为什么、在哪里学；讲课、作业辅导与判题进入外部平台。保留旧练习记录，不继续扩展自建辅导体系。

这一版的衡量标准是：用户能否做成事、创作者能否得到真实反馈。不能用新增页面数、接口数、播放量或测试数量替代产品完成度。

### 1.1 六个一级板块（Owner 提出的对外结构）

**首页 / 校园 / 资料 / 校圈 / 开源广场 / 个人中心。** 搜索、发布和消息是跨板块操作，不再额外创建一级板块。原 M01–M08 保留为内部功能编号，供接口、测试和任务引用，不是八个顶级导航入口。

| 板块 | 用户主要目的 | 板块包含的内容 | 一次访问应能完成什么 |
|---|---|---|---|
| 首页 | 知道今天有什么值得关注 | 编辑精选新闻/专题、近期热点、校圈精选、活动机会、个人关注更新 | 看懂一条当前信息，进入原内容或采取报名、关注、收藏等下一步行动 |
| 校园 | 办校园里的事、了解校园 | 地图、课程目录、地点、活动、教室/体育场馆预约服务，设施信息与校园影像 | 找到地点/课程，了解活动条件，进入真实预约流程或订阅开放提醒 |
| 资料 | 找到合适版本的学习材料，也能上传分享 | 四六级、期中/期末/月考及其他课程资料；笔记、实验、课件、雅思等分类 | 按课程和考核找到可预览的资料，识别年份/答案/来源，上传到正确分类 |
| 校圈 | 交流、讨论、参考校园口碑 | 动态、贴吧式话题、课程/教师口碑、精选阅读、组队讨论 | 发帖或参与讨论，按星级人数与真实原话判断课程，找到原评论和回应 |
| 开源广场 | 发现能用的项目、展示作品、参与创作 | 项目推荐、学术前沿、创作投稿、工具和代码、竞赛/科研项目及协作任务 | 看演示，读详细使用说明，取得正确入口；或者提交自己的项目并得到反馈 |
| 个人中心 | 管理身份、成果和下一步发展 | 学院/专业等个人资料、兴趣、生涯规划、等级/贡献、奖项、作品、草稿、收藏、消息、外部账号 | 管理公开范围，查看真实成果与下一步任务，关联 GitHub / 洛谷等平台作品 |

首页是全站内容的精选入口。校园、资料、校圈和开源广场分别保存对应详情，个人中心集中管理与本人有关的记录；各入口引用同一内容 ID 和版本。

### 1.2 首页：持续更新的校园编辑页

Owner 已明确淘汰当前首页以网站自我介绍和炫技为中心的内容安排。重新设计时，首要内容来自真实新闻、热点和同学活动；关于网站的信息不再占据主要阅读路径，既有动画是否保留由 Opus 根据实际内容决定。

借鉴 Apple 首页以独立主题、短标题、明确行动入口组织内容的方式。把主题换为校内新闻、近期机会、校园创作者和精选作品；不直接照搬商品介绍文案或将首页做成大篇功能说明。[Apple 中国大陆首页](https://www.apple.com.cn/)

内容约定：

- 编辑精选为主，显示选题时间、内容来源和推荐理由；可包含一条重点新闻、一组近期机会或一个校园创作者专题，具体篇幅和排布交 Opus。
- 新闻区分学校原始通知、学术/行业报道、本站公告和学生投稿。保留事件发生时间与发布时间；临近报名、取消、延期不能仅凭摘要推送。
- 热点说明范围和时间窗口，可结合近期有效讨论与编辑核对；不以全站累计点赞做永久榜，也不把争议评价自动推成新闻。
- 个人关注更新是补充，由用户关注的作者、项目、课程、话题和活动生成。未登录时提供公共精选；不能因没有兴趣档案而显示空首页。
- 推荐内容过期、撤回或来源失效时同步更新首页。编辑可设置展示期限，暂无可用稿件时展示真实近期内容，不编造热点或互动量。
- 首页校圈预览、项目预览均进入原详情；不另存副本、不重开评论区。首页推荐不自动变成系统通知。

### 1.3 校园：课程与生活服务放在一起

课程目录提供课程名/编号、学院、经核对的开课信息、先修建议及相关资料。学生体验来自校圈的同一份评分和评论；校园课程页可展示评分摘要并直达原评，不能另收一套评分。教师资料与授课关系也保持唯一记录。

地图关联地点、活动、楼宇和设施。同一场活动有地点、时间、适用人群、主办来源、报名与变更信息；可以从首页、校圈帖或地图进入，但活动事实只维护一份。课程能关联教学楼，活动能关联场馆，空位反馈能标记现场时间。

教室与体育场馆预约采用逐级接入：

1. 整理真实场馆/教室信息、官方开放规则与预约入口，订阅开放/截止提醒。
2. 若获得可用的正式接口，再展示真实空位和刷新时间，提供预填与本人确认。
3. 确认预约成功必须有原系统的有效结果。未接入时如实标记仅有入口/提醒，不使用虚构余位或“预约成功”提示。

用户所说的预约功能保留在目标内；当前学校接口可行性尚未验证，本轮不连接教务账号或索取凭据。图书馆、洗衣机等设施信息遵循相同的来源和时效规则。

#### 1.3.1 校园插画与活动标点（2026-10-06 补充）

Owner 要求学院路与沙河分别绘制，参考主题乐园导览的立体感；卫星只作为绘制依据。优先保留真实校园范围与建筑体量，不能为画面丰富扩大校园。制作、对位与审稿见 `CAMPUS_MAP_ART.md` / `ART_REVIEW.md`。本节为功能规格，新增活动状态与订阅逻辑尚未因此实现。

- **三层分离：** 插画表现建筑与环境；地点层维护 `campusId/placeId`、真实地面轮廓及经核对的入口；活动层使用稳定 `eventId` 关联地点与时段。替换插画不改地点坐标，不能将立面屋顶的像素中心当作导航入口。待核对观察点不进入导航。
- **活动标点：** 至少能区分即将开始、进行中、已结束、已取消；状态由有来源的起止时间与明确取消记录决定，不用热度猜测。默认显示当前与所选时段活动，历史记录可查，过期或取消的活动不继续作为“正在举行”展示。未知时间显示待确认；仅日期信息不制造精确开场倒计时。
- **点击后的实际信息：** 标题、校区/地点、时间及精度、面向人群、主办来源、原通知、更新时间、报名入口、已核对入口照片和“关注变更 / 到这里”。报名、余位、实际预约结果分别说明；没有接口就明确为原站入口。
- **筛选与拥挤处理：** 今日、本周、活动类型与校区使用同一条件作用于地图和列表；同地点多场活动能展开。密集标点由 Opus 决定聚合方式，但数字必须等于当前筛选下的真实活动数。手机、键盘及减少动态效果模式均能通过列表找到同一活动。
- **用户共建：** 特殊地点/临时装置可附照片、拍摄时间、入口和有效期限，审核后显示。长期地点与临时活动分别保存；用户撤回、维护者更正或期限结束后更新关联入口，保留必要的来源/版本记录。
- **导航与订阅：** 坐标必须注明坐标系，按目标导航服务约定转换一次并验证；不知道位置时不给出虚构目的地。订阅的地点/时间/取消变更按 `eventId + version` 去重；取消关注后停止新通知。预约仍采用提醒、预填与本人确认，不由地图自动抢占资源。

地图专项验收：两校区不会混入对方内容；活动在所有入口共用一份状态；取消/过期即时反映在筛选和标点；插画更新后已核验入口位置不漂移；入口未核对时不冒充可导航；每个标点在列表中有同一详情；空列表不填充虚构活动。

### 1.4 资料：明确分类，也明确上传路径

建议采用“内容类型 + 课程 + 考核类型 + 年份/学期”筛选，不强迫用户进入很深的文件夹才能找到文件：

- 语言考试：四六级真题/答案/听力，以及雅思等外部资源与用户可分享材料。
- 校内考核：期中、期末、月考/阶段测验等；课程没有月考就不制造对应栏目或试卷。
- 日常学习材料：课件、笔记、实验、复习提纲和公开题目资料。真题、模拟题、个人整理分别标识。

**用户上传路径：资料 → 上传资料 → 选择课程或考试 → 填写年份/学期与考核类型 → 拖入文件或粘贴来源链接 → 预览与查重提示 → 提交审核 → 查看结果。** 个人中心的“发布/草稿”进入同一个表单。找不到课程时可提交待核对的课程建议，不强制错选。

以“高等数学 A1 / 2025–2026 学年 / 第一学期 / 期末 / 试卷+答案”为说明性分类示例，具体年份与科目以文件实际内容为准，不作为已有资源。保存课程编号、文件类型/大小、原作者、上传者、许可/分享依据、来源、答案状态和版本。

同一资料关联多个课程或专题时共用原文件与版本；用户保留自己的补充说明和署名。上传后可以看见提取、预览、待审、退回和已公开状态。草稿和未公开文件不能进入公开搜索；扫描件无 OCR 时保留原件并说明未识别。

### 1.5 校圈：话题交流与校园口碑共用社区基础

校圈包含日常动态、主题吧和口碑评价，三者可相互关联，但互动含义不同。话题帖按讨论组织；课程/教师评价保留评分对象、学期背景、人数和分布。对任意普通同学的个人打分不在本次“虎扑系统”的范围内。

借鉴 App Store 的星级与完整文字评论分层。教师卡继续使用照片、姓名/学院、教学体验星级、人数和高赞原话；课程评分独立。未审核照片或缺失资料使用真实缺省状态，不虚构人物素材。[Apple 评分与评论说明](https://developer.apple.com/app-store/ratings-and-reviews/)

评价页保留 Owner 已确认的可开启“高赞评论弹幕墙”；正文正常阅读，点击原话定位原评论。教师/课程主体可提供回应和事实更正渠道，回应不直接删除负面体验或改变分数。版式和视觉交给 Opus，不把整个论坛强行变成评分卡片。

### 1.6 开源广场：项目推荐与学术前沿可切换

Owner 已确认以项目推荐为主，学术前沿单独切换。项目推荐一次聚焦一个创意，有短视频则播放真实演示，无视频则明确展示图文。浏览方式之外保留列表、分类和搜索，便于带着具体问题来的同学。

项目面对全校：日常效率、设计与媒体、开发工具、算法、机电/机器人、嵌入式、科研复现和竞赛作品均可投稿。推荐依据兴趣、基础、设备、关注与“不感兴趣”等反馈，学院/专业只作用户自愿提供的补充信号，不能把其他方向排除在外。

每个项目都能继续到第 4 节规定的详细档案、源码/下载、运行条件、具体步骤、失败处理和协作入口。视频弹幕按第 5 节实现，视频只是演示媒介，不替代可检索的文字说明。

学术前沿不止转发标题：每条说明“发生了什么、原始证据在哪、适合谁关注、与哪些课程/工具/项目有关”。区分论文、预印本、正式发表、作者公告和媒体报道；能关联原论文、代码、数据与本站复现档案。后续阅读工作区从此进入，已收藏的阅读任务由个人中心管理。

创作者投稿支持两条路线：关联已有 GitHub 仓库；或者先提交说明、演示及可分享的源码包/文件，再补充仓库。源代码版本协作继续依托 GitHub 等平台，本站保存作品档案、版本附件、讨论与任务；本站不因接受源码附件就宣称实现 Git 托管。竞赛信息、招募和专题作为分类/关联对象，不新增顶级导航。

### 1.7 个人中心：私人管理与公开作品集分开

个人中心包含学院、专业、年级、校区、兴趣、发展目标和每周可用时间等可选资料；GitHub / 洛谷 / 力扣等入口按用户需要启用。非计算机专业同学也能展示项目、校园创作、设计、实验和奖项，不必须绑定开发平台。

私人管理内容包括草稿、预约、通知、收藏、同步设置和个人生涯计划；公开主页只展示用户选择公开的资料、作品、贡献和奖项。身份核验材料、联系方式与证书原件不默认公开。奖项记录比赛名称/届次、级别、个人角色、证据及“自填/已核验”状态，不能把自填头衔变成认证。

生涯规划连接具体行动：目标 → 能力缺口 → 资料/课程/竞赛/项目 → 当前任务 → 阶段作品。可以调整目标与时间；不给用户凭空生成“完成的经历”。等级沿第 7 节，外部刷题活动与本站有效贡献分开。

**本人洛谷题解的同步方案（新增需求，尚未实现）：**

1. 用户关联公开账号，或提交本人题解链接；先区分公开链接和已核验作者身份。
2. 展示可导入候选：题解标题、原作者/账号、题目编号、原链接、发布时间、最近核对时间；“原站已发布”与“经原站收录为题解”分别核对，不能只凭文章标题宣称官方认可。
3. 用户预览并选择展示哪些作品；默认保存作品卡与原站入口。全文镜像须由作者选择并具备相应分享依据；支持的读取方式需验证，不默认抓取所有文章。
4. 经用户选择后可订阅来源更新；上游修改/删除时标记差异或失效，不默默覆盖站内补充内容。停用同步与删除本站展示分别提供操作。
5. 使用原文章标识去重；同一作品同步多次不重复计贡献，AI 不改写成另一份“原创题解”。未找到合法稳定接口时提供手工导入与原链接，不冒充实时同步。

洛谷对主题库题解有独立的审核和内容要求；当前公开开放平台文档不能证明存在满足上述个人文章同步需求的通用接口。以上为本站产品流程提案，技术可行性需要后续逐项验证。[洛谷题解规范](https://help.luogu.com.cn/rules/academic/solution-standard)、[洛谷开放平台](https://docs.lgapi.cn/open/)

### 1.8 六板块之间如何互通

| 场景 | 正确的关联 | 统一规则 |
|---|---|---|
| 校园课程与校圈评价 | 课程事实页 ↔ 对应课程/教师评价 | 同一对象、同一评分，不重复收评 |
| 首页与其他板块 | 精选预览 → 原新闻、活动、项目或帖子 | 一份详情、一套评论和版本；点击后明确去向 |
| 资料与课程 | 一份资料关联课程/考试/学期 | 文件不重复复制，搜索与上传使用同一分类 |
| 项目与校圈 | 项目详情 ↔ 关联讨论/招募 | 同一讨论记录可从不同入口访问，不重复计互动 |
| 项目与个人中心 | 公开作品 ↔ 我的投稿/成果/任务 | 原作者、本站投稿者、贡献者角色分别记录 |
| 学术前沿与科研 | 原始研究 → 代码/数据 → 本站复现与阅读任务 | 来源版本明确，不把新闻解读当作实验验证 |

跨站搜索和本站搜索在每个板块可达。全局搜索覆盖六板块公开内容，板块内搜索默认限定范围且能切换；未登录不可搜索私有草稿和个人预约。统一“发布”按资料/项目/动态/活动等类型进入对应模板。

### 1.9 交给 Opus 前的范围说明

## 4. M01 / M02：项目必须从“听说不错”变成“我知道怎么用”

### 4.1 三种推荐，三种承诺

| 分类 | 筛选理由 | 必须展示 | 不能暗示 |
|---|---|---|---|
| 实用精选 | 能解决明确问题，入门说明和入口齐全 | 适用情境、准备条件、核对时间、验证证据或未验证状态 | 没跑过就写“实测可用” |
| 创意发现 | 交互、用途或组合方式值得借鉴 | 演示来源、创意点、已实现范围 | 概念视频等同于已有功能 |
| 潜力项目 | 早期方向有价值，适合跟进或参与 | 完成度、已知缺口、缺哪些贡献 | 只有源码也写成开箱即用 |

“严选”是可核对的编辑标准。资料读取、编辑核对、复现通过分别显示，不能合成一个含义模糊的认证。GitHub Star 只是一项公开参考，不决定精选资格。

### 4.2 每份详细档案的内容契约

| 部分 | 必须回答的具体问题 | 依据或验收 |
|---|---|---|
| 用途与边界 | 它解决什么问题？给 2–3 个具体使用场景；不适合什么需求？ | 每个能力可定位 README、文档或实际演示；未确定的写清楚 |
| 使用门槛 | 新手能否使用？需要什么基础、系统/架构、设备、磁盘、账号、服务与费用？ | 未说明配置不猜最低要求；硬件项目包含物料、设备条件与成本来源 |
| 功能详解 | 主要能力的输入、操作、输出分别是什么？ | 选 3–5 项核心能力解释，功能列表不能只翻译标题 |
| 演示与版本 | 谁制作的视频？展示哪个版本，是否实机？ | 区分原作者演示、同学试用、概念表现；保留原链接与时间 |
| 获取方式 | 在哪试用、下载哪个包、源码在哪里？ | 官方仓库、文档、演示站、Release；按系统/架构区分附件，写明版本与核对时间 |
| 最小成功路线 | 从准备到得到第一个结果分别做什么？ | 必要步骤、工作目录、配置项、预期输出、成功标志；区分文档整理和实际验证 |
| 常见失败与退出 | 依赖失败、模型不可用、设备不符怎么办？如何停用或清理？ | 引用原项目文档/Issue；没有可靠解法就标记待验证，不编造命令 |
| 工作流连接 | 它能接收/输出什么格式，能和哪些工具配合？ | 标出版本、接口、额外配置和已验证组合；不能仅因两个项目都接 AI 就宣称互通 |
| 维护与限制 | 许可、最近维护、归档状态、收费依赖、已知限制是什么？ | 来源时间与证据；旧导读遇到版本变化标记待复核 |
| 参与方式 | 有哪些新手任务、课程基础、组队需求和可复用成果？ | 站内任务或原仓库真实 Issue；本站投稿者与原项目作者分开署名 |

发现流只展示有助于选择的短内容；项目详情承载完整说明，不用固定短字数砍掉操作细节。用户应能按“零代码使用 / 本地运行 / 自行开发”选择原项目实际支持的路线，不支持的路线不能虚构。

安装包与源码压缩包分开。下载地址从官方 Release 资产或项目文档核对，标明预发布状态；原站提供摘要值时保留用于校验。没有发行包就明确说明需要从源码运行。[GitHub Releases 官方接口](https://docs.github.com/en/rest/releases/releases)

### 4.3 AI 导读的处理链

1. 读取受限范围内的公开元数据、README、安装文档、相关示例、依赖/配置说明和发布记录；记录文件路径、提交版本、原文位置和获取时间。
2. 先提取可证实的事实及缺失项，再生成中文说明和操作路线。网页与仓库里的内容作为资料，不能被当成系统指令执行。
3. 每段实质性结论有证据入口；推断、缺项、来自作者的说法、本站试用结果分别标识。摘要失败保留原文和最近可用版本，不生成假结论。
4. 命令和配置必须有核对过的来源、适用版本和用途，凭据只出现占位符；生成清单不意味着网站自动替用户执行下载、安装或脚本。
5. 编辑核对后进入精选；复现通过须另有设备、版本、操作及结果记录。上游更新使相关步骤进入待复核，不自动继承旧“通过”。

当前 github_guides.py 尚未做到这条完整流程。下一轮先做三个真实案例：一个低门槛实用工具、一个开发/自动化工具、一个机电/机器人相关项目；项目选择时再核对来源。本轮不填虚构演示、用户、评论或验证数据。

### 4.4 推荐应该让人更容易行动

抖音公开说明介绍了召回、排序和多样性等环节，并非可直接复制的完整线上算法。[抖音算法公开说明](https://trust.douyin.com/algorithm/)

本站先采用可解释、可调的规则：

- 候选：当前版本已通过审核的内容，结合用户主动选择的兴趣、课程基础、设备条件和关注对象；给低热度新作者保留探索机会。
- 排序：优先内容完整、目标相关、条件适配、来源新鲜；“实用、创意、潜力”分别表达不同选择理由。明确不感兴趣、隐藏作者/话题应及时生效。
- 打散：避免连续同作者、同用途和同仓库不同视频霸屏；同仓库保留一份规范项目档案，多个视频作为其媒体。
- 控制：可选最新、关注、推荐，能查看理由、重置兴趣、关闭个性化。不将关注流重新按热度排序，不把不同场景强行塞成同一个榜单。
- 验证：记录用户自愿反馈的“找到有用入口、实际尝试、遇到障碍、完成成果”。点击下载不能直接算安装成功，停留时间也不能代替有用性。

## 5. 视频、弹幕和评论：三种对象分开定义

Owner 已确认评价页采用可开启的“高赞评论弹幕墙”，正文保持清晰。项目短视频按原需求提供时间轴弹幕，两处独立开关。Opus 决定视觉实现，但不得遮挡核心阅读和操作。

| 对象 | 功能定义 | 与长期记录的关系 |
|---|---|---|
| 项目视频弹幕 | 绑定某个视频版本的播放时间，例如在操作出现时说“这里还要配置环境变量” | 可点击进入该时间点；有价值的排错经作者确认后整理到项目说明 |
| 口碑弹幕墙 | 可开启的独立区域，按点赞数选取已公开评价的原话，点击定位原评论 | 不是再造一套评分；原评论修改/撤回后引文同步变化，点赞仍归原评论 |
| 正常评论 | 可检索、可回复、可引用的长期讨论 | 项目评论、视频评论、课程评价保持各自对象与权限，不能混算教师和课程评分 |

视频来源支持三种状态：本站审核后的上传视频、原平台允许且播放器可用的嵌入、仅提供原站链接。每种都注明作者、原地址和版本。嵌入失败退回有效链接，不把图文卡称为演示视频。

同步弹幕只用于能读取播放时间的播放器。本站视频绑定 clipId、mediaVersion、timeMs；跳转、暂停、倍速均跟随真实播放位置。替换视频不继承旧时间轴弹幕。外部平台没有可用播放器事件时，只提供原站播放与讨论，不用假计时伪装同步。

弹幕共同要求：

- 可开关，提供密度、字号/透明度或等效可读性控制；手机限制同时显示数量，避开字幕、播放器控制和重要演示区域。具体视觉参数由 Opus 实测决定。
- 尊重减少动态效果设置；提供静态列表，键盘和触屏可操作。评价页默认保留安静的正常阅读，不在教师照片、星级或输入框上覆盖滚动文字。
- 发布需登录及邮箱验证；长度、频率、重复内容限制，支持举报、屏蔽与撤回。处于待审、撤回或隐藏状态的内容不得继续在播放缓存中公开。
- 原始评论和引文版本关联；高赞墙从至少有一赞的公开评价中按点赞数降序选择，同赞数优先最近发布。不够时少展示，没有高赞时说明暂无高赞评价；卡片仍可按既有规则展示“最新评价”，不得混称“高赞”。取消点赞、修改和撤回均重算。匿名评价的引文、通知、搜索、点赞返回和贡献/经验侧边信息均不能反推出作者。
- 弹幕不自动增加评价人数、星级、贡献或经验。用户不因关闭弹幕失去任何基本内容。

视频验收：一个真实演示从上传、转码、审核到项目播放，弹幕在暂停/拖动/倍速时仍对应画面；删除后再次请求及播放均不出现。口碑验收：开启/关闭墙不影响阅读，点击可到原评，修改/撤回后不显示过期原话，匿名身份无旁路泄露。

## 6. GitHub / 洛谷连接：从几个图标变成可用的关联

### GitHub

- 账户：已验证的 GitHub 身份与站内 userId 关联。填写个人链接不能当作验证；绑定 GitHub 也不自动证明拥有所有展示的仓库。
- 项目：仓库固定标识与站内项目关联；统一 README、文档、Release、Issue、PR、good first issue 与维护状态入口。迁移/改名保留对应关系和原链接。
- 关注：用户选择接收版本或站内讨论更新；上游刷新失败显示上次成功时间。本站 Star 与 GitHub Star 分开，站内点击不默默代表用户操作站外账号。
- 贡献：经过核验的 PR、文档或复现可关联成果；外部提交数量、Star 数不直接兑换站内经验或管理权限。
- 运行：缓存、限流退避、失败状态和更新时间明确。需要 OAuth 或密钥的能力以实际配置状态展示；当前 GitHub 登录尚未配置。

### 洛谷及其他练习平台

- 先做可靠的题目、题单、比赛、用户主页入口；与本站课程、算法专题、项目所需能力相连。可收藏、整理学习路线、记录自己的反思。
- 原站完成做题、提交和判题；本站不新建 OJ、不代刷、不将自填“完成”显示成官方 AC。力扣等可沿同一套外部入口约定扩展。
- 公共链接、用户自填记录、经验证的平台记录分栏；展示来源、同步时间和是否验证。同步失败保留旧值和失效说明，不归零。
- 现有 scripts/build-community.mjs 使用构建期抓取和公开页面解析，不能宣传为成熟的绑定同步服务。服务端同步、解绑、权限、频率和隐私仍需实现与验收。
- 洛谷官方开放平台介绍以题库/评测服务为主，不能据此假定已存在免费通用用户同步或 OAuth 接口。具体身份核验和统计读取能力需单独核查；无法接入时明确降级为原站链接和手工整理，不索取密码或浏览器 Cookie。[洛谷官方介绍](https://help.luogu.com.cn/about-us)、[开放平台文档](https://docs.lgapi.cn/open/)

每个平台关联记录至少区分：站内用户、平台固定 ID、公开链接、验证方式/状态、可见字段、最近成功时间、异常原因。首次导入要让用户预览并确认；旧 GitHub 用户名主页逐步映射到统一身份，原链接继续可达，不直接把同名用户合并。

## 7. M08 等级：能看见成长，不能靠刷量制造权威

借鉴 B 站等级的可见成长感。本站经验与阈值是自己的试行规则，不复制消费、投币或刷播放激励，也不宣称下表是 B 站现行规则。B 站账户升级说明可参看其[官方帮助入口](https://www.bilibili.com/h5/faq)。

### 7.1 等级、贡献、身份三条线

| 记录 | 表示什么 | 不表示什么 |
|---|---|---|
| Lv / 经验进度 | 在本站被采纳的参与积累 | 学术水平、专业资格或对别人评价的额外权重 |
| 贡献记录 / 领域徽章 | 做了什么、谁采纳、证据在哪里 | 用登录天数换“科研专家” |
| 认证 / 管理角色 | 经核验身份、明确授予的维护职责 | 高等级自动获得封禁、看匿名作者或审核权限 |

试行等级提案：Lv0 为未验证邮箱；完成验证成为 Lv1。Lv2 / Lv3 / Lv4 / Lv5 / Lv6 分别需要累计 100 / 500 / 1500 / 4000 / 10000 有效经验。阈值可配置，先用真实贡献分布回放，再决定上线数值。所有已验证账号具备正常投稿和评价机会，不以等级压低新人的声音。

试行事件提案：被采纳的有效资料修正或答复 +10；通过核对的原创项目使用说明 +20；验收通过的任务成果 +30；可复核的复现报告 +40。不同项目难度不由字数或附件数量衡量；同一成果只取一个适用事件，不叠加刷分。

规则要求：

- 使用可追溯事件账本：事件 ID、成果对象/版本、采纳人、规则版本、分值、撤销记录。重复请求或重复入库不重复奖励；撤回和误采纳能够扣回，用户能看到原因。
- 普通发帖、观看、签到、弹幕、点赞、GitHub Star、导入刷题数不直接奖励经验。高赞可以帮助发现内容，但不能直接等同于已核验贡献。
- 公开匿名课评不生成可被他人对照的个人经验流水或贡献热力图。匿名身份保护覆盖搜索、通知、个人页与事件查询。
- 旧贡献先去重、试算、由用户查看对应关系；本轮不自动补发经验。用户可查看自己的完整明细，公开主页仅展示允许公开的成果。
- 展示等级进度同时给出下一项可参与的真实任务，避免只有数字。报名协作、阅读和负面课程反馈不要求高等级。

验收：一个成果的重复采纳只能计一次；修改版本不会无限加分；撤销后经验/等级/展示同步更新；普通用户不能伪造采纳事件；管理员身份与等级变动互不替代。

## 8. 其他已确定功能的边界保持一致

- 教师卡片仍按照片、姓名/学院、教学体验星级/人数、高赞原话、课程学期与原评链接组织。照片缺失使用占位，少于五人标注样本少。教师整体与开课记录分别评分；一账号一位教师保留一份有效评价，可修改。新弹幕不能破坏这些规则。
- 校圈的公开动态不等于好友私密朋友圈。互关可见、匿名校圈、私信、投票和吧主权限目前未完成；后续单独定义，不把公开内容标签改成私密就上线。知乎精选默认原链接、来源作者、推荐理由和适用人群；当前没有自动采集全文能力。
- 资料覆盖全校课程，通用主科、英语和雅思等作为分类扩展；资源版本、年份、难度和适用背景必须可筛。站内用于整理和引导，不继续开发自建辅导。
- 校园影像与介绍、创作者宣传稿、临时趣味地点保留；图书馆、教室、运动场、洗衣机信息区分官方实时、用户现场反馈、静态说明。预约保持提醒、预填、本人确认；未取得可用接口前不承诺实时空位或自动抢约。
- 竞赛包括计算机、机电和机器人等，先给官方资格、规则年份、截止时间、校内选拔及历届项目；变更核对后再通知订阅者。生涯规划连接真实资料和项目，允许按目标与时间调整。
- 科研以阅读、引用导出、专题、复现和协作为主：论文、代码提交、数据版本、环境、设备、步骤、结果、失败记录和他人验证相连。AI 论文摘要必须能定位原文，不能伪造研究结论。
- 开源自部署和可替换服务继续保留；账号、上传、对象存储、邮件、模型、外部同步均应有配置说明和诚实的不可用状态。公网部署仍不在本轮任务内。

## 9. 统一数据与协作规则

这是设计约束，不是新增 API 已可调用的承诺。新字段与端点在下一阶段先写接口契约，再由双方接入。

1. 一个站内 userId；外部账号不另建一套本地用户。一份规范项目 Entry，GitHub 仓库、导读版本、演示、任务和讨论通过关系关联；发现流使用投影，不复制完整项目数据。
2. 教师、课程、开课记录各有独立 ID，不能因课程名相同合并；原始评价保留独立隐私与统计规则。视频时间轴绑定具体媒体版本，评价弹幕引用原评及版本。
3. Star=收藏/认可，Watch=订阅事件，Like=喜欢一条内容，Useful=有帮助反馈，Contribution=被采纳成果，XP=根据有效事件计算的成长值。事件不能相互冒充。
4. 推荐共用反馈含义、设置和来源校验；项目发现与校圈可以采用不同排序策略。上游撤回、取消精选、用户屏蔽应同步影响缓存与可见性。
5. 各模块统一处理加载、空数据、未登录、未配置、来源失败、权限不足、待审核、过期。没有内容时如实引导投稿，不能用演示统计填充真实社区。
6. 保留现有链接、草稿、评价和本地练习记录。旧个人数据导入经用户确认；任何合并/迁移先列映射和回退方案，不在整理规格时动数据库。
7. Codex 交付字段、权限、事件、异常状态和测试；Opus 交付页面组织、美术与交互。每次只打通一条完整使用路径，双方在同一组真实内容和同一配置环境上验收。

## 11. 联合验收场景

1. 新同学选择兴趣和设备，看到一个项目及推荐理由，打开演示与详解，区分下载包/源码并完成最小操作；无法运行的设备得到真实说明。完成时间与卡点记录下来，不预先宣称“零门槛五分钟”。
2. 创作者在页面提交项目、来源、版本与演示；另一账号审核通过后公开，第三人收藏、讨论或认领任务；更新只通知已选择相关订阅的人，取消后停止新通知。
3. 视频弹幕暂停、跳转、倍速和移动端播放均正确；举报/撤回后公开不可见；外链视频无法同步时明确降级。评价墙能打开原评论，关闭后完整内容仍可读。
4. 外部账户链接与已验证绑定区分；GitHub / 洛谷来源失败展示上次成功时间。用户可解绑及调整公开字段，本站 Star 不影响站外账户。
5. 同一成果重复投稿或回放采纳请求不重复计贡献/经验；撤销后记录和等级同步变化。匿名课评不能经通知、头像、用户 ID、经验变化或公开活动反查。
6. 未登录、无照片、无评分、少样本、无视频、AI 不可用、空推荐和断网均有明确状态；普通用户不能读取他人草稿、待审媒体或匿名审计身份。
7. 手机能完成搜索、看演示、读步骤、投稿和查看退回原因；页面可读性与弹幕开关由 Opus 实测验收，接口测试不能替代这一项。

### 13.2 课程事实、评分和目录缺失

本轮代码核对：courses.json 共 13 项，其中 campus-catalogue 为 3、learning-topic 为 10；3 项校内目录也尚未核验官方课程代码。这不是完整培养方案。GuideCourse.id 现为稳定字符串，CourseOffering.id 为具体开课 UUID；保持这两个层级，不换成课程名称作为关联键。

- 课程事实增加字段级来源与核对日期。官方代码、学院、学分、开课学期可未知；学习主题仅展示资源分类，不填写虚构学分或授课教师。
- 考核方式归具体开课/学期，状态分为已确认有、已确认无、未知。未知时允许上传者选“待核对”并附来源；不能把资料缺失判断为课程没有期中/月考。
- 没找到课程时，用户保存资料草稿并提交课程建议：名称、学院/专业（可空）、原始来源和补充说明。维护者确认新增或关联已有课程，再通知用户检查映射；不偷偷把近似名称合并。
- 课程建议有待核对、已关联、需补充、未采纳四种结果；历史资料保留原填写内容和更正记录。疑似同课跨学院时先并列提示，由维护者确认。
- 评分遵守已确认规则：0 人暂无评分；1–4 人显示真实均分、人数及“样本较少”；平均值保留一位小数，不因 App Store 风格而隐藏它。
- 现有课程总览 stats.count 是历次开课的评价条数，同一人可能评价不同开课；不能直接标成独立人数。总览先写“历次开课 N 条评价”，后续接口分别提供 reviewCount 与 participantCount；教师和单次开课的一人一评规则不变。课程总览均分按有效开课评价计算，说明聚合口径，可切换到具体学期。
- 主题名搜索可以命中课程候选，但星级、人数与教师关系只来自实际课程/开课记录。搜索结果不得把学习主题伪装为已开设课程。

### 13.3 首页来源、精选与机会的数据要求

保留 Source 负责抓取配置、Entry 负责原内容，新增“精选引用”负责首页展示。取消首页精选不删除原文，也不撤销原内容的合法发布状态。新闻更新不会因首页编辑改了一句话而重发一次。

| 对象 | 必需字段或状态（新增部分为草案） | 用户看见的结果 |
|---|---|---|
| 来源登记 | sourceId、名称、URL、来源类型、采集方式、启停、lastSuccess、错误；补充内容/图片使用范围、核对人/时间 | 学校原始通知、学院新闻、行业报道、本站公告、学生投稿分别标识 |
| 精选引用 | selectionId、entryId、reviewedRevision、标题/导语、推荐理由、所属板块、editorId、checkedAt、startsAt、expiresAt、可选媒体引用 | 知道为什么推荐、何时核对；点击进入原详情和原始来源 |
| 机会信息 | audience、deadline、deadlinePrecision、timezone、registrationUrl、ruleVersion、checkedAt、status | 判断适用人群、截止是否明确，以及去哪里报名 |
| 媒体引用 | mediaId、来源、作者、使用依据、altText、与事件的关系 | 原图、授权配图、示意图分别说明；缺图片不阻止真实内容出现 |
| 推荐集合 | selected / following / recent，生成时间、内容版本、空/失败/过期状态 | 编辑精选与个人关注各有语义；关注为空不等于全站无内容 |

现有 Source 已有采集方式、启停、最近尝试/成功和错误；Entry 已有标题、摘要、链接、适用人群、deadline 等通用字段。精选排期、独立 editorId、媒体使用依据、事件日期与采集状态的完整组合尚未实现。

编辑流程：来源内容进入待核对候选 → 核对时间/人群/原链接 → 编辑选题与期限 → 指定版本通过 → 到期退出首页精选。事实原文发生实质变化时显示待复核；截止/资格等关键变化先退出行动推荐，再核对后通知主动订阅者。正常过期内容可留在历史检索，但行动按钮不再显示“立即报名”。

日期必须区分发布时间、事件时间、报名截止和本站核对时间。只有日期没有具体时刻时显示“当天截止，具体时刻待核”，不自行制造秒级倒计时；存储时区/精度，展示按北京时间。原始通知中适用条件未知时明确未知，不按用户学院推断“你有资格”。

首页多区命中同一内容或同一原文时去重；用户关注作者和话题同时命中，只生成一条对应更新。新内容少时显示最近核对且仍有效的内容，不以随机数据占满区域。

后台每项编辑任务有负责人、待处理原因、上次核对和下一次复查时间。暂未指定编辑时显示未分配，不承诺自动每周精选或固定审核时限。Opus 提出的首批至少 10 条真实内容可作为启动筹备目标；目前没有因写入目标就完成采集或编辑。

### 13.4 资料上传：让用户知道每一步发生了什么

一个资料条目可以有试卷、答案、听力、讲义等不同角色附件，不用同文件名猜角色。草案字段为 courseId / offeringId、academicYear / term、assessmentType、materialType、attachments[].role、answerStatus、source、credit、license、rightsBasis。现有 course/courses/year/uploads/credit/license/rightsConfirmed 可复用，其余结构化字段需扩展校验和存储。

| 状态 | 用户可做什么 | 必须避免的误导 |
|---|---|---|
| 草稿 | 填分类、补来源、保存并继续 | 离开前说明是否已保存；不把本机草稿说成已同步账号 |
| 上传/解析 | 查看文件进度和提取结果，删除附件或重试 | 解析失败不丢已填写信息，不把 needs-ocr 写成识别完成 |
| 预览 | 看文件、文字和公开后的署名，核对缺项/疑似重复 | 私有重复文件的作者、标题或是否存在不向其他用户泄露 |
| 待审核 | 查看提交版本、提交时间与退回/撤回入口 | 不承诺未建立的“24 小时审核完成” |
| 需修改 | 按字段提示补充来源、分类、答案说明等 | 退回理由具体，不能只有“审核失败” |
| 已公开 | 获取稳定链接，补充版本与更正 | 修订审核中仍展示此前已公开版本，不能先公开新附件 |
| 撤回/受限 | 作者看到原因和可用处理路径 | 搜索、精选、预览缓存同步遵循状态；附件权限仍由服务端检查 |

现有上传接口限制为每个文件 25 MB，支持 PDF/TXT/MD/CSV、常用图片、ZIP、STL/STEP、IPYNB；视频走独立流程。界面需要直接告知当前能力，不能宣称支持尚未实现的 DOCX/PPTX 解析、断点续传或任意大文件。压缩包目前不解压、不执行。

查重分两种：同哈希为确定相同字节；相似标题只作提示。标题建议先按同课程、年份、考核类型缩小候选，再忽略空白/标点进行比较；A/B 卷、答案/无答案、不同年份必须保留区别。用户可选择关联现有资料、提交新版本或说明差异，合并由维护者确认。

分享依据采用明确选项：本人原创、原作者已有明确许可、已获得分享授权、仅提供原链接、许可待核。保留原文许可名称/网址，作者原创内容可自行指定许可，系统不默认给别人材料套 MIT 或 CC 协议。许可待核时可保存草稿或仅提供合适的来源入口，公开附件须核对依据。

表单确认文案草案：“我已核对资料来源、作者与分享范围；上传附件具有可核对的分享依据。仅分享链接时，本页会标明前往原站。” 这句不能代替实际许可核对；授权凭据只给必要的审核人员，不在公开页面原样显示。许可具体选项、授权材料存储尚需实现，不把现有 rightsConfirmed 一个布尔值宣传成完整核验。

### 13.5 项目引导：把详解转成可执行的使用路线

在第 4 节详细档案基础上，为每个实际支持的路线提供结构化信息：routeId、适用系统/架构、前置条件、预计准备内容、费用来源、步骤、预期结果、对应证据、已验证环境和日期。零代码试用、本地运行、自行开发分别存在；项目没提供的路线不自动生成。

每步包含目的、操作、需要的输入、完成标志和失败时去向。下载步骤必须落到确定版本或说明动态 latest；演示视频可用章节时间点关联步骤。API key、私有文件和付款始终由用户在自己的环境处理，搭建清单不替用户执行未经确认的操作。

用户选择“加入我的尝试”后，个人中心出现未开始 / 准备中 / 尝试中 / 已完成 / 遇到问题 / 已放弃。完成可由本人记录，但标为自报；有设备、版本和证据的审核结果才标“复现已核对”。失败记录可转项目讨论，暴露日志前提示预览需要公开的内容；作者根据采纳结果修正文档。

推荐反馈细化为“不相关 / 条件不符合 / 已经看过 / 来源失效 / 已尝试有帮助”，不感兴趣可撤销并说明过滤范围。基础和设备条件用于推荐解释，不能从一次浏览推断专业水平。公共排序优先当前版本经过核对、使用路线清楚的内容，给新作者探索机会；具体权重仍待真实使用记录检验。

### 13.6 个人成果：导入、发布和经验分开

外部作品状态依次为发现候选、待用户确认、已关联展示、来源变化待检查、失效/停用。首次导入不自动发布全部历史内容；后续自动检查由用户选择。导入方式、作者证明、原站文章编号、原始链接、版本摘要、lastSuccess 与失败原因保留。

GitHub 仓库和洛谷题解属于不同作品类型。洛谷已发表文章、题解收录、用户自填练习完成分别标识；数据源不提供证据就不出现认证徽章。原文更新不能静默覆盖本站独立注释，原文删除后保留适当的失效状态并停止继续推荐。

导入一份作品是关联动作，不直接奖励经验。原创整理被采纳、任务验收或复现核对才进入相应贡献事件；同一成果在多个平台展示也不重复奖励。奖项同样有自填、待核验、已核验、已更正状态，证书和可公开摘要分开。

现有 Member.external_links 是公开链接，major 当前也出现在公开资料接口；学院、年级等 preferences 目前只在本人接口返回。按字段选择公开范围、站内 ID 查询、平台绑定记录、洛谷题解同步和奖项模型都需要新增实现，前端不能先显示能生效的隐私开关。

### 13.7 跨板块行为与提示文案

| 情境 | 建议反馈 | 后续操作 |
|---|---|---|
| 无公开资料 | 这门课还没有可公开的资料 | 上传资料或提交来源，不推荐未审私有文件 |
| 学期考核未知 | 该学期的考核方式还未核对 | 提交来源，允许保存待核草稿 |
| 精选来源失败 | 暂时无法更新，最近成功核对于…… | 查看原文或重试，不改写旧成功时间 |
| AI 未配置 | 暂无 AI 导读，可查看原文和已核对说明 | 原仓库/文档仍可访问；不制造摘要 |
| 视频只支持外链 | 前往原站看演示 | 留下本站文字说明；不启用假同步弹幕 |
| 自动同步未接入 | 当前支持添加原文链接，自动同步尚未接入 | 手工导入作品卡或稍后再试 |
| 预约缺少确认结果 | 尚未获得预约结果，请到原系统确认 | 不显示成功，不新增“已预约”记录 |
| 两人同时编辑 | 内容已有更新，请先核对差异 | 保留本次草稿，重新读取版本；禁止静默覆盖 |

未登录用户可浏览公开内容，发起收藏/投稿时登录后回到原对象与操作；不要丢掉筛选和已输入文本。个人设置仅在服务器确认保存后显示成功；无法连接时明确未同步。跨页面进入同一项目或课程时共享原 ID，不重复创建。

### 13.9 给下一轮实现的验收用例

| 编号 | 操作与预期 |
|---|---|
| F01 | 首页同原文命中新闻、热点、关注三个候选时按规则去重；撤回原条目后首页和公开检索均不可见 |
| F02 | 报名只给出日期时不显示猜测的秒级倒计时；延期候选未经核对不自动发送新报名提醒 |
| F03 | 编辑精选到期退出推荐但保留合法原详情；改导语不重新制造一条原新闻 |
| F04 | 学习主题不展示成已开校内课程；不存在官方代码时不生成假编号；课程建议合并保留旧链接与作者说明 |
| F05 | 同一课程不同学期的评价总览分别显示条数与人数口径；1–4 样本有真实均分和提示，0 样本无 0 分 |
| F06 | 上传失败重试不丢表单；另一人的私有同哈希附件不触发公开查重提示；A/B 卷和年份差异不自动合并 |
| F07 | 修改已公开资料时新附件保持待审权限；撤回后公开展示与缓存符合规则，未审版本不从历史接口泄露 |
| F08 | 只有源码附件的项目在能力未扩展时明确不能提交；能力完成后从真实投稿、审核到查看全过程验收 |
| F09 | 未配置 AI、没有演示或平台只支持外链时仍有真实原文路径；不会出现假导读、假视频和假弹幕时间轴 |
| F10 | 外部作品首次导入由用户逐项确认；修改/删除产生检查状态；取消同步停止新抓取，重复导入不增加经验 |
| F11 | 旧 GitHub 名称只有可核验绑定唯一命中才跳站内公开页；不能因手填链接夺取另一个人的主页 |
| F12 | 手机从首页或搜索进入课程/项目后能继续预览、投稿或收藏；登录返回原对象，关闭弹幕仍能读全内容 |

上述 F 编号是待实现验收定义，不是已通过测试。Opus 完成页面后，Codex 与其使用同一配置和内容逐条核对，保留截图/请求结果/失败说明，不能只以构建成功验收。
