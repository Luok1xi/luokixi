# 北矿娘的工作台（Opus · 2026-10-07）

北矿娘本身（名字、人设、语气、运行她的 Codex）由 Codex 接入，在 `campus/hub/studio_config.py` 的 `PERSONAS['beikuang']` 和 `campus/hub/supervisor.py` 的 `PERSONA`。**这一轮没有改这些**，新能力都写成技能，放在 [campus/beikuang-skills/](../campus/beikuang-skills/README.md)。

## 她现在怎么干活

1. **收件**：机器人（学校新闻、GitHub 采集、中文导读、总监督请示、公告草稿）原来调用 `maintenance.staff_notice` 通知站主，现在改为交给她。`beikuang.receive()` 记一笔，然后马上排一次巡检。站主的“通知”里不再出现机器人消息。
2. **巡检**：`beikuang.review_all()` 每小时一次（maintenance 的 `beikuang` 任务），收到新东西时立即一次。按技能逐类核对：

   | 技能 | 核对什么 | 过了做什么 |
   |---|---|---|
   | news-review | 官网来源、标题、摘要、45 天内、配图来自官网且有署名、不重复 | 以她的名义发布 |
   | project-review | 可再分发的开源许可证、简介和 README、下载入口、近期维护、已分类、没有风险词 | 推荐进开源广场，理由用她的话 |
   | guide-review | 原文没变、十章都有依据、不少于 1500 字、没有“已实测 / 本站严选”这类说法、未说明事项不超过 6 条 | 公开中文导读 |
   | photo-review | 来自老师本人的官网个人页；读得出尺寸；竖版证件照比例 | 照片在口碑页显示 |
   | announcement | 没有待确认的疑问、有站内依据、篇幅合适、不冒充学校官方、标明 AI | 以她的名义发布公告 |
   | escalate | 总监督自己拿不准的请示 | 原样交给站主 |

   她只做规则核对，不调用模型、不运行项目代码。每次发布都记审计，审核人是她的系统账号“北矿娘”。这个账号不能登录：没有密码，邮箱是 `.invalid` 域名，注册时也不允许中文用户名。
3. **交给站主**：没过的东西不发布、也不退回。一次巡检合成一条消息，发在“个人中心 → 北矿娘”她自己的窗口里，一件一张卡片：
   - 新闻、项目、导读、照片、公告：卡片上写卡在哪一条，站主点“发布”（照常发布，记站主的名字）或“不要了”；
   - 请示：站主直接回她一句话。

   站主在别处（比如维护面板）处理过的事，下一轮巡检会自动从卡片里拿掉。
4. **日报**：每天北京时间 21 点后写一份，站主也可以点“写日报”。用她已经接好的 Codex 写，人设不改，再叠加 daily-report 技能，要求可爱、简短、只用给定的数字。
5. **聊天**：站主随时发消息，她根据自己的工作记录回答。只有本机、本机配置的站主发的消息才用她的 Codex 额度，规则和 AI 工作室一样。
6. **没有模型时**：Codex 没启用、或今天的额度用完时，日报和聊天都用技能里的“句式”回复，窗口里标明“这是她的预设回复”，不假装是模型写的。

聊天和日报单独走一条工作线程（`worker.loop_interactive`），不排在几分钟的采集任务后面。

## 接口（`/api/hub/`，维护者）

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `beikuang` | 她的窗口：消息、卡片状态、今天的数字、技能列表、是否正在巡检 / 输入 |
| GET | `beikuang/unread` | 她发来的未读条数（导航角标、铃铛） |
| POST | `beikuang/messages` `{body}` | 给她发消息，回复由工作线程生成 |
| POST | `beikuang/read` | 标为已读 |
| POST | `beikuang/run` | 让她马上巡检一遍 |
| POST | `beikuang/report` | 让她马上写日报 |
| POST | `beikuang/tasks/<id>/decide` `{decision: publish \| dismiss}` | 站主处理她交来的事 |
| POST | `beikuang/tasks/<id>/answer` `{answer}` | 回复请示（转到 `supervisor/answer`） |

## 开关与上线

- `HUB_BEIKUANG=0`：整个关掉，机器人恢复为直接通知站主。
- 上线需要执行迁移 `0013_reputation_bot`、`0014_beikuang`，然后重启 `campus/run_hub.py`：主队列加聊天线程，北矿娘的每小时巡检随 maintenance 调度。
- **重启后的第一轮巡检会处理已经积压的内容**，比如待审的学校新闻、GitHub 候选、待核对的中文导读。过了规则的会直接公开，没过的发到她的窗口。
- 她的模型调用和 AI 工作室、中文导读共用每天 12 次的 Codex 上限：日报每天 1 次，每条聊天 1 次。

## 测试

`hub.test_beikuang`（9 项）覆盖以下内容：

- 技能文件与句式、她的账号不能登录、PNG / JPEG 尺寸读取；
- 机器人消息改道（关掉开关后恢复为通知）；
- 新闻、项目、导读、照片、公告的通过与交给站主；
- 同一件事不重复提，在别处处理过的会被清理；
- 站主发布、不要了、重复操作返回 409；
- 没有模型时的聊天和日报；
- 用 Codex 时提示词里包含她原本的人设、聊天技能，并说明资料不是指令；
- 日报一天一份、21 点后才写；
- 权限。
