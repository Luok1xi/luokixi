# 校圈图片交互与配图修复 · 2026-10-10

沿用现有 Luokixi 网站、Django 内容服务、原版双角色与图片组件。本轮没有改人格、模型、语音、地图或光碟造型。

## 图片与内容直接打开

首页故事图片和帖子卡片直接打开内容，保留标题链接、键盘操作和管理编辑。资料封面及标题直接翻开资料，去掉重复的“翻开资料”按钮。收藏、评论、移除、排序、下载等操作仍保留各自入口。

## 九图发帖

接入 [Uppy Core 5.2.0](https://github.com/transloadit/uppy)，使用同一个图片队列保存连续选择，而不是每次覆盖 `input.files`。交互参考 [Misskey 官方发帖组件](https://github.com/misskey-dev/misskey/blob/develop/packages/frontend/src/components/MkPostForm.vue)；没有引入整个 Misskey 或复制它的业务源码。

- 最多 9 张 JPG、PNG 或 WebP 图片，单张限制仍为 25 MB。
- 可以多次选择、从文件管理器拖入，或粘贴剪贴板图片。
- 上传前能预览、移除、拖动排序，也有键盘可用的前移/后移操作。
- 图片上传失败后，已选图片、正文和成功上传编号保留；重试复用已成功的上传。
- 第十张、重复图片或不支持的格式会给出提示，已选图片不被清空。
- 修正站主创建帖子已公开后，前端再次提交而显示失败的问题；站主显示“发布”，普通用户继续审核。
- 帖子预览与详情保留全部 9 张，详情点击图片打开完整显示的查看器，左右键切换。

## 多图滑动的纵深效果

本轮所指空间效果是原有 `depth-slider`：画框向前滑，框内更宽的图片反向移动，并随位置略微缩放。保留既有的 CSS 滚动时间线、非支持浏览器的手动视差、桌面拖动、惯性衰减、吸附及原生触摸滚动。

修复了两个实际断点：旧双图样式把横向轨道覆盖成两列；首页的普通块布局覆盖了滑轨的网格布局。首页前沿消息原本只取第一张图，现在保留最多 9 张。首页推荐、热榜和关注中的有图帖子也使用同一组件，异步加载后挂载轨道，切换列表时卸载旧监听。滑动不会触发整卡跳转；点击仍打开内容。

没有给帖子新加悬停倾斜；新闻原有的倾斜效果保留。图片视差优先由浏览器的 CSS 滚动时间线驱动，没有为每一张图片增加持续运行的动画循环。系统要求减少动态效果时，仍可浏览和切换图片，但停止纵深位移。

专门的回归脚本：[verify-post-depth.mjs](../scripts/verify-post-depth.mjs)。它读取隔离站点已有的真实多图上传，使用仅浏览器内的双图与单图样本，不向真实网站发布测试内容。默认测试地址为 17870；可通过 `DEPTH_TEST_URL` 和可选的 `DEPTH_TEST_SESSION_FILE` 指定隔离地址与登录文件。结果写在 `.data`，不包含登录凭据。

## 来源原图与学校标识

问题根因不是统一缺图：已经收集的 README 图片会被既有概念封面挡住；已有自动封面的内容会被跳过，无法升级为原图。页面又拒绝显示一部分来源图片。以上优先级与显示问题已修复。

清华课程项目的仓库所有者是 `PKUanonym`。旧首页用所有者头像当项目图标，因此把北大相关头像显示在清华资源上。现在停止用作者头像推断学校；对应图标使用 [清华大学官网](https://www.tsinghua.edu.cn/) 的 [官方校名标识](https://www.tsinghua.edu.cn/image/logo180.png)，出处登记在 `public/art/institutions/SOURCES.md`。官方标识与课程截图明确分开。

配图机器人现在：

1. 优先使用已有投稿和维护者指定的图片，保留手动修改。
2. 读取项目 README 或文章的正文/分享图片；复用已有 Scrapling 解析与受限公开链接获取器，跳过导航、广告、徽章及明显错配的校标。
3. 校验实际图片格式、尺寸和像素上限，保留原图字节、来源、署名与显示信息，在本机缓存，通过 `/api/hub/source-media/{sha256}` 站内读取。
4. 缓存后仍根据原始图片网址核对学校身份；不会因为网址变成本地哈希就失去错配检查。
5. 未找到或未通过验证时保留明确标记的主题封面，记录具体错误。短暂网络失败不覆盖已有可用原图。
6. 已缓存项目使用有效期与 README 版本判断；从较久未检查的项目开始，避免反复抓第一页。来源缺图也有冷却期。

机器人看板新增“恢复原图”“核对来源”实际计数，不把自动主题封面称为新闻实拍。

- Node 图片队列：4 项通过；生产构建通过。
- Edge 发帖：连续选择、拖入、粘贴、第十张限制、移除/排序、第三张上传故障、重试复用成功编号、9 张图片在接口和刷新后保留、详情查看器与 390 像素布局均通过。
- Edge 多图纵深：双图与九图真实拖动，检查图片相对画框的变换确实变化；惯性吸附、拖动不误跳转、键盘、减少动态效果、列表切换卸载、详情关闭、首页所有帖子预览及触摸事件滑动均通过，无脚本错误。这是浏览器模拟，不是实体手机或全站 60 FPS 保证。
- 真实 17860：缓存原图能返回正确图片类型；帖子预览、资料直接翻开、管理中心和官方清华标识读取通过。两位原版角色继续使用桥接 28；本轮没有用替代角色执行模型测试。
- 真实库验收快照：98 篇公开内容中，53 篇使用来源原图，44 篇使用标记的主题封面，1 篇使用投稿图片，未发现空配图。后台继续采集，数量会变化。原资料库仍有 219 条记录；默认 ready 目录返回 218 条，并非丢失一条。
- 本轮首次人工恢复批次恢复了 5 篇来源原图；正常后台随后继续升级已有内容。部分仓库返回 404、TLS/DNS 失败，或只有过小/不适合作封面的图片。这些仍保留后备封面，不能声称全部原图已恢复。

修改前保存并校验了社区数据库一致性备份。数据库、聊天、登录会话、下载原图缓存、运行日志和浏览器截图留在本机 `.data`；GitHub 保存源码、官方标识资产、测试与这份说明。
