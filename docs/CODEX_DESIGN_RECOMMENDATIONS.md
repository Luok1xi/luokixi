# 给 Opus 的排布与美术建议

2026-10-06。**Owner 最新分工：网页排布由 Opus 落地，内容由 Opus 与 Codex 共创。** 本文是建议，不覆盖现有设计系统，不要求照搬草稿。当前页面没有按这些建议改版。

## 设计目标

把“查资料、看作品、参与贡献”放在第一层。让作品有视觉表现力，让正文容易读，让操作明确。借鉴苹果官网的留白和内容层次，保留 Luokixi 自己的名字、图形和校园语境。

本次实际查看了苹果中国官网的桌面页面，并截图对照现有首页和知识库。苹果首屏把产品名、短说明、主要动作与大幅主体图分开，后续主题使用不同背景分区。这个方法适合共创入口；知识库属于工具页，不应为了大图把搜索推到第二屏。[参考：苹果官网](https://www.apple.com.cn/)

## 建议的全站关系

- 首页：介绍能在这里完成的事，给“查资料”和“看项目”明确入口。
- 知识库：课程、真题、笔记、采集与复习。四级/六级/校内卷继续作为课程入口，避免在顶层无限增加导航项。
- 校园共创：项目、题解、交流、贡献。
- 我的学习：浏览器本地题目足迹、收藏、备份；在有账号前不写“云同步”或“已登录”。

导航如何整合由你决定。建议在主导航上区分“资料”和“创作”，并保留当前页指示、键盘焦点与移动菜单。

## 知识库：把搜索带回首屏

现在 1440×1000 的首屏中，大标题、连接提示、计数、标签占据了较多高度，搜索约在页面中部。建议顺序改为：

```text
知识库                         收录资料
一行说明
[ 搜索课程、年份或题目片段                搜索 ]
课程 / 来源 / 类型              共 n 份
资料检索  网络来源  我的复习
结果列表
```

- 页面标题可以比首页小，不必在工具页重复占两行的宣传句。
- “本机已连接”降为小状态，只在异常时展开可操作的提示。
- 一条结果最多保留课程、年份、类型三项主要信息；来源、扫描识别状态放第二层。
- 主动作使用一致名称，例如“查看原卷”；摘录/加入复习属于详情中的下一步。
- 搜索命中突出关键词和页码；未 OCR 的原卷准确标为“仅按目录检索”。
- 目录、正文、参考答案明确区分，避免让扫描识别文字看起来比原件更权威。

## 共创页：一处视觉焦点，下面专心阅读

```text
短引导 + 大标题 + 两项动作   | 原创机电概念图
------------------------------------------------
项目广场 / 题解与足迹 / 交流与协作 / 贡献记录
搜索与方向筛选
主内容：项目条目/讨论/贡献   | 初次参与指引
```

这是信息关系示意，不是像素级排版约束。草稿 `proposals/community-structure.html` 仅记录建议的栏目、表单和文案；未接 JS/CSS，未注册为网页，不宜直接发布。

建议首屏标题：“让你的作品，成为别人的起点。”
副文案：“从一道题的解法，到一台机器人的诞生。把知识分享出来，让想法继续生长。”
主动作“发现项目”，次动作“分享我的作品”。避免三个以上同等强调的按钮。

项目列表应优先显示：做什么、适合谁、项目阶段、许可、能否复现、需要什么帮助。星标和技术栈可以辅助筛选，不用星标代替可信度。项目详情里接 README、代码仓库、Issue、贡献指南，减少用户在多站之间找入口的负担。[参考：GitHub README](https://docs.github.com/en/repositories/managing-your-repositorys-settings-and-features/customizing-your-repository/about-readmes)

## 美术交付

- `public/art/community-engineering.webp`：1536×1024，78,482 字节。原创 AI 机电静物图，银色机架、蓝色电路板、齿轮、电机与橙色线材；适合共创主视觉或项目方向引导。
- 图片无文字，标题由网页排版。不要把它标成某位同学的已完成作品，也不要把概念装配当作接线/加工依据。
- 生成提示词和来源在 `public/art/community-art.json`，使用内置 image_gen 生成；WebP 仅做格式压缩。
- 建议主视觉保持 3:2 比例，主体完整；移动端放在标题后。深色页面可保留浅色“展示台”画框，不强行降低图片曝光。
- 真实项目优先用作者授权的实拍、原理图或截图；没有图的项目用统一代码图标，不用概念图冒充实物。

## 可读性与交互验收建议

继续使用当前 `tokens.css`，不再添加另一套颜色。长说明控制行长；正文 17px 左右、行距约 1.7，辅助元信息不承担重要操作。数据区减少渐变和发光。

- 390px 下无横向页面溢出；标签换行，筛选器不挤成竖排文字。
- 链接有可辨认的样式；只在 hover 才出现的动作也能用键盘触达。
- 主操作触控区域至少约 44px；图标按钮必须有文字标签或无障碍名称。
- 浅色/深色分别检查普通文字、禁用态、输入框、焦点；普通文字目标对比度至少 4.5:1。
- 贡献日历除了颜色，也提供日期、数量和明细；空数据不画假绿格。
- 空列表给下一步：分享第一个项目、换条件、导出草稿。未连接不把按钮伪装成成功。
- 详情/表单显示字段错误，关闭后保留草稿；提交时阻止重复点击。
- 原动画保持你的整体控制，并尊重系统减少动态效果设置。

## 可以逐步加入的实用设计

1. **可复现标记**：由其他人提交复现条件与结果，核对后标记；不自动给所有项目打勾。
2. **课程与项目互相连接**：例如“电机控制”项目关联电路、控制原理和嵌入式课程，而不是只按编程语言组织。
3. **新手可参与事项**：呈现补文档、复现、改错等小任务，链接到真实 Issue；不造虚假待办。
4. **交接包**：项目阶段、已知问题、器材清单、上一届维护者的交接记录，服务社团换届。
5. **过期提醒**：显示来源核对日期；下架、迁移、失效时保留原因及替代链接。
6. **多维贡献**：把代码、资料、复现、纠错、解释都记下来；不做刺激灌水的简单发帖排行榜。

以上 6 项为产品建议，未全部实现。已实现的数据能力和边界见 `COMMUNITY_API.md`；内容与运营规则见 `COMMUNITY_CONTENT.md`。
