# 多图纵深滑轨流畅性 · 2026-10-10

本轮沿用 Agrumea Farm 参考的原 `depth-slider`，只优化其输入与运动调度。画框尺寸、128% 图片宽度、反向视差、缩放、图片来源与原入场效果保留；没有新增动效库。

## 已修改

- 高频鼠标移动先保存最后输入和短速度历史，由一个显示帧回调更新滚动位置；松手前补上尚未绘制的最后输入。
- 原生 CSS 滚动视差且没有控件的预览，不再监听滚动安排空的 JavaScript 动画帧。尺寸缓存观察滑轨与等宽首框，不逐张观察九个画框。
- 松手保留原 192 ms 惯性投影，投影到已有吸附点；复用 `spring-step.js` 解析解及 `SPRINGS.smooth`，一次完成惯性与吸附。浏览器原生吸附在这段鼠标运动期间暂停，准确到达终点后恢复。
- 停住后松手不沿用旧速度；到边界立即结束；取消或丢失捕获只就近吸附。阈值前离开、拖动中隐藏、卸载和减少动态设置切换都有清理。
- 重新拖动可从当前位置打断运动。空闲滚轮不被干预；触摸继续原生滚动；按钮与左右键继续浏览器平滑切换，不走鼠标弹簧。

## 验收

生产构建、已有共享运动 7 项测试，以及 `verify-post-depth.mjs` 的 Edge 页面回归通过：双图/九图实际拖动、惯性吸附、不误打开帖子、键盘、触摸、减少动态、首页各列表、详情打开关闭与监听卸载。

性能比较使用同一个 headless Microsoft Edge、30 条九图滑轨、相同模拟图片和输入；基线是 `155f563`。各实现正常速度与固定 4 倍 CPU 节流各测两轮：

| 可直接计数的工作 | 原版 | 本版 |
| --- | ---: | ---: |
| 一批 120 次指针移动后的滚动写入 | 119 | 1 |
| 30 条原生无控件轨道滚动的额外 JS 帧请求 | 30 | 0 |
| 准确吸附点停住再松手的旧速度额外偏离 | 122–184 px | 0 px |

同一脚本还检查空闲滚轮、阈值前离开、丢失捕获、隐藏零尺寸恢复、兼容浏览器的手动视差、减少动态设置和卸载；反向视差矩阵保持一致。原始结果在本机 `campus/.data/depth-motion-20261010/compare-result.json`。

这些计数证明多余工作和错误惯性减少。Headless 的帧间隔只代表渲染器调度，不能当作这台 5070 或实体屏幕的呈现帧率；模拟图片也不能证明真实高分辨率图片的解码表现。本轮没有宣称全站 60 FPS。

## 复测

`scripts/measure-depth-motion.mjs` 只创建浏览器内的隔离样本，不发帖、不写真实数据库、不调用模型、不访问外网。默认结果写入本机 `.data`，不上传。

```bash
node scripts/measure-depth-motion.mjs --mode candidate
node scripts/measure-depth-motion.mjs --mode compare --baseline-ref 155f563
```

若没有完整 Git 历史，可以用 `--baseline-dir` 或 `DEPTH_BASELINE_DIR` 指向保存的原 `depth-slider.js` 和 `.css`。需要本机 Microsoft Edge 与仓库的 Playwright 依赖。
