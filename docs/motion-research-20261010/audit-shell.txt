SUMMARY: The shell already has a solid base. Navigation is a Vite MPA that opts into cross-document View Transitions in head.html:7. Direction is worked out from board rank, page depth and lane (shell.js:24-57), saved in pageswap and read before the first frame, prerender included (head.html:16-35). Speculation rules prerender the light pages and only prefetch the heavy ones (head.html:39-42). motion.css (Opus v2) has iOS curves for page pushes (a full-screen push at ≤760px), @starting-style dialogs that rise as bottom sheets on phones, press scale, scroll-timeline reveals and the Spotlight glow. fx.js/motion.js add pop(), rollTo(), the openFrom/closeTo FLIP and springs sampled into linear(). Below that layer, the actual interaction logic is per page and inconsistent, and several shared paths are broken. These were measured in a production build served on :5181 with headless Chromium at 1280x800 and 390x844: (1) On phones the FAB's 发布 sheet renders at y=-360…-17, fully off screen, because .gn's backdrop-filter becomes the containing block for the fixed-position .gn-pub. (2) There are four copy-pasted toast() functions; their enter transition never runs (opacity is 1 at t=0, with 0 animations), and an uncleared inner 300ms timer hides the next toast about 300ms after it appears. (3) History Back can play the forward slide, because traversals ignore navigationType (Back from materials to reputation played 'forward'). (4) Async-rendered pages lose scroll position on Back when bfcache misses (materials 750→359, circle 1172→550). (5) A leftover View Transition layer in components.css:1489-1550, plus v3.css:740, overrides motion.css durations (old root runs 240ms instead of 160ms, 'same' runs 240/240), which gives an equal-length crossfade that dips to the canvas. (6) There are four dialog families. .dlg bottom sheets on phones drop in by -12px instead of rising. Esc on the FLIP thread dialog closes instantly. Tapping the backdrop closes some sheets and not others. No sheet except story.js supports drag-to-dismiss or closing with Back. (7) About 45 handlers set btn.disabled with no visual change, since there is no .btn:disabled or [aria-busy] style anywhere. Likes and stars wait a full server round trip before the heart fills (pessimistic updates). Login and error messages go into status lines at the top of the page, often off screen (circle.html:68, reputation.html:14). Native confirm() and prompt() appear five times. There is no haptic layer, and press scales are defined about nine times with different values. The fix is a small set of shared, native (WAAPI/CSS) primitives in the shell — toast, act/optimistic toggle, sheet, confirm sheet, scroll restore and a corrected VT layer — rather than more page-level animation. One caveat: in `vite dev`, CSS is injected by JS, so cross-document VT runs the UA default 250ms crossfade. Motion should be judged on the built site (17860 serves dist, so the Owner sees the real CSS).
