SUMMARY: These app pages get their motion almost entirely from CSS transitions that switch on class toggles, plus the shared shell layer (motion.css page transitions, press scale, sheet dialogs for non-.dlg on mobile; fx.js pop/rollTo/openFrom; motion.js springs). None of them use GSAP. The interaction logic underneath is the weak part. Nearly every page re-renders whole regions with innerHTML after each network reply or poll: project.js rebuilds #main 4 times on load, beikuang-chat rebuilds the thread every 2.5 s while she is typing, studio every 2.2 s, reservations every 30 s, and me.js on every hashchange and async reply. Typed text, open <details>, focus and scroll position get lost, and content enters as a jump instead of an animation. Nothing is optimistic. Star in project.js and online save in discover.js wait for the server and then re-render, and read-all on notifications sets st.notes=null and refetches. So fx.pop/rollTo, which already exist for exactly this, are never used. Mobile does not feel like iOS. The map bottom sheet only toggles on a click (no drag, no detents, and a 78%→70% height jump when a detail opens). The discover/download/guide .dlg dialogs float as cards from the top (probe: top 42px of 844) instead of rising as sheets. The me nav wraps into 3 rows of chips. Small correctness issues: the discover toast never animates in (hidden removed and .is-on added in the same frame; probe shows opacity 1 at 6 ms with 0 animations); there are three copies of toast and three segmented-control implementations; infinite pin/ring animations on the map are not gated by data-live; mobile rail icons are 60px and 38px side by side; and the 收藏 tab shows "需要登录" even when local saved projects exist (they only appear under 本机足迹, as bare URLs, not clickable to a detail page). The biggest wins: a Draggable+Inertia+Flip 收藏夹 desk, optimistic toggles, keyed patching (diff against existing nodes instead of replacing them, so only new nodes animate in), an iOS detent sheet shared by the map and dialogs, and in-panel push/pop. All of these stay inside transform/opacity and the existing spring tokens. Note: the kankan-shoucang repo could not be read from this session (GitHub 403), so the desk spec below is built from the owner's description and the data actually available (server Star rows with id/slug/data/collection plus local notebook.savedProjects). Vite on 5184 was stopped; the repo is unmodified. The only console errors were the expected 502s from the backend proxy.
