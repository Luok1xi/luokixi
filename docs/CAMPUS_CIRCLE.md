# 校圈：校园动态、兴趣吧与精选阅读

2026-10-06。Owner 新要求：朋友圈式动态、贴吧式社区、高质量知乎内容推荐，并研究抖音推荐机制。所有页面、布局、美术和交互呈现仍由 Opus 负责，Codex 只实现功能、数据与接口。

## 调研结论及证据范围

北矿助手在开发者发布的 App Store 版本记录中，已经列出校圈、关注、投票、匿名发帖、评论、举报与屏蔽；本轮没有登录它的校内账号做实机体验。因此不能把“它只是官网链接合集”作为事实，也不能依据个别评论断定其当前稳定性。[北矿助手公开介绍及更新记录](https://apps.apple.com/cn/app/北矿助手/id6451183563)

贴吧的官方帮助包含违规帖子、恢复帖子及投诉吧主等处理入口。值得借鉴的是围绕共同主题长期积累讨论，以及管理决定可反馈、可申诉；当前资料属于官方历史帮助，未据此声称新版客户端按钮位置。[贴吧投诉帮助](https://tieba.baidu.com/tb/tousu/help.html)

抖音的官方交互说明公开了多路召回、多轮排序以及多样性调整；双塔召回、Wide & Deep 是示例中的部分模型，实际系统更复杂。它不等于几项点赞率加权，也没有在此公开可复制的完整权重、数据和训练体系。[官方推荐原理](https://trust.douyin.com/algorithm/)

官方另一篇说明介绍从内容池到召回、排序的流程，以及基于交互预测后续行为的思路。本站借鉴分阶段筛选及探索机制；当前数据量下先采用可解释规则，不声称已经训练出抖音同等模型。[从零开始了解推荐系统](https://trust.douyin.com/article/15358?channel=home&enter_from=channel_page)

知乎通用协议页面本轮未能完整读取，也未验证可供本站使用的官方全文采集接口。本轮采用原文链接和投稿者自己的推荐理由，不建立知乎全文镜像；自动采集和全文 AI 摘要不标为已接入。若后续获得作者授权或正式内容合作，再增加相应适配器。

## 校圈应该解决什么

下面是结合矿大场景的产品判断，尚未经过学生访谈或线上 A/B 实验验证：

| 需求 | 形成的内容 | 可继续做的事 |
| --- | --- | --- |
| 分享今天做了什么 | 短文字、照片、创作进展 | 关注作者、看项目、招募搭档 |
| 一个问题持续讨论 | 主题长帖、经验楼、资源整理 | 收藏、搜索、关联课程或比赛 |
| 找同好 | 摄影、机器人、开源、运动等兴趣吧 | 订阅主题、找到合作的人 |
| 读值得花时间的内容 | 知乎及其他原站的精选阅读卡 | 看适用基础和推荐理由，前往原文，留下实践反馈 |
| 把经验变成成果 | 动态关联项目/资料，讨论沉淀成文档 | 作者确认后形成教程、项目进展或复现记录 |

同一份帖子可被动态流和话题吧引用，保留一个编号、一套回复和版本。课程口碑继续使用独立评价数据；匿名评价不通过关注、作者主页或推荐理由泄露身份。

首版校圈是**公开署名动态与关注流**。它没有互关可见权限、私信、朋友圈私密相册或全站拉黑，不应在页面上出现这些已可用的选项。后续要做互关可见，必须同步覆盖搜索、附件、回复、通知、推荐和公开个人主页的访问判断。

## 推荐如何工作

当前规则版本为 campus-explicit-v1，代码在 campus/hub/circle.py；以下权重是本站启动用的工程初值，需用真实体验调整，绝不是抖音参数。

1. **候选：**最近 200 条公开校圈内容、最近核对的 100 条精选、最近 100 条已关注作者/话题内容，合并去重。
2. **过滤：**未审核、撤回、停用话题、用户不感兴趣或已隐藏的作者/话题不进入校圈流。站外阅读卡进入推荐前必须有针对当前公开版本的维护者精选。
3. **打分：**新鲜度最高 2 分（按首次公开时间衰减）；当前版本精选 +3；主动选择的兴趣标签每项 +2、最多 +4；关注作者 +3；订阅话题 +2；经账号去重的“有帮助”反馈最高 +1。
4. **重排：**尽可能使每组 12 条同一作者不超过 2 条、同一话题不超过 4 条；每第 5 位优先给反馈较少的新内容一个探索机会。候选不足时放宽数量约束。这是可解释的探索规则，不是统计意义上的随机实验或保证 20% 新作者曝光。
5. **稳定翻页：**同一轮使用绑定会话与筛选条件的签名游标，最多 200 条，30 分钟过期。后续页重新检查可见性、撤回、版本和精选状态；条件变了要求刷新，避免翻页时反复打乱。

推荐附具体理由，例如“来自你关注的创作者”“符合你选择的兴趣：机器人”“维护者精选：有可复现步骤”。精选改动后理由实时核对，不继承旧核对说明。

用户可以选择最新、关注作者、订阅话题、精选阅读；关闭个性化后推荐入口按首次发布时间排序。匿名访客看到一般推荐，没有个人兴趣档案。重置推荐清除兴趣与反馈，保留主动关注、隐藏名单及开关；隐藏作者/话题仅作用于自己的校圈，不等同全站阻止对方查看公开内容。

本站点赞、Star 收藏、关注、贡献是四件不同的事。普通发帖不自动增加贡献，精选内容经核对后才记录一项，取消精选、改版或撤回后退出贡献统计；同一原文的重复分享保留投稿，推荐流去重，不重复计精选贡献。点赞不直接进入当前排序，不能靠刷回复抬高名次。

本轮不记录浏览时长、滑动轨迹或跨站阅读行为。后续如果引入行为反馈，先说明采集范围、保存周期和退出方式；评估目标优先是找到有用内容、进入真实项目、完成合作，而不是单独追求刷得更久。

## 知乎精选的具体做法

每张卡保留原平台、原文链接、原作者、投稿者、适用人群和推荐理由。维护者核对当前版本后显示精选理由与核对时间；文章修订、原链接变化或投稿编辑需要重新核对。知乎链接去掉分享跟踪参数，同原文在一轮推荐里只出现一次。

推荐理由回答“这篇能帮矿大同学做什么”，例如：判断研究方向、理解竞赛路线、准备开源贡献。高赞数不自动等于高质量；优先核对论据、适用背景、时间和原始材料，允许不同观点并存。初期靠学生推荐、维护者评选积累真实内容，不造作者、点赞或已读统计。

AI 后续可以整理获得授权/允许处理的正文，但必须有原文证据、原作者和生成标记；只拿到标题时不能编造全文摘要。当前接口只提供阅读卡，不提供知乎全文下载、站内阅读全文、自动登录抓取或付费内容提取。

“推送”当前指站内推荐流，以及用户明确订阅的创作者/话题新帖通知。通知默认关闭，可取消；同帖同时命中作者和话题只通知一次。没有开通系统级 Web Push。

## 已实现的功能范围

- 公开动态、长帖、站外阅读三种格式；最多 9 张照片，公开仅去 EXIF 预览，原件保持作者/维护者权限。
- 复用 Entry 的草稿、修改、提交、审核、讨论、收藏、内容关注、举报、撤回。校圈投稿不能自审。
- 6 个空话题吧的幂等初始化命令；管理员可新增或停用，已有记录不覆盖。
- 作者关注、话题订阅与独立通知开关；点赞按人按公开版本去重，“有帮助”“不感兴趣”可清除。
- 推荐、最新、关注、订阅话题、精选阅读；搜索正文及标题、按吧筛选；推荐偏好和隐藏名单仅本人可读。
- 版本绑定的维护者精选和贡献撤回；知乎原链接校验、跟踪参数移除、推荐流原文去重。

尚待的社区增强：互关可见、匿名校圈、二级回复/楼中楼、投票、吧主分级权限、置顶和精华索引、私信、系统级推送、授权知乎采集、统一跨项目/短视频推荐。原生短视频已有另一套接口，目前只关联教师、课程或项目，本轮未新增校圈视频附件类型。

Opus 决定上述能力放在哪个页面以及如何排布；Codex 没有新增校圈 HTML、样式或页面脚本。先通过最小完整流程验收，再扩展社交可见范围和自动化采集。

## 接口与 Opus 接入

统一前缀 /api/hub/；复用 cookie 会话、X-CSRFToken。写操作需要登录且邮箱验证，审核和精选另需 staff。客户端方法在 campus/hub-client.js，不操作 DOM。

| 接口 | 内容 |
| --- | --- |
| GET circle/capabilities | 当前支持格式、公开范围、算法版本，明确无自动知乎导入及 Web Push |
| GET circle/boards | active 话题、自己的订阅/通知状态、可见帖子数 |
| POST circle/boards | staff；id/name/description/rules/active |
| POST circle/posts | {data} 创建 topic 草稿，返回原 Entry 结构 |
| GET circle/posts/{id} | 公开卡片；已隐藏/撤回 404 |
| GET circle/feed | lane=recommended/latest/following/boards/reading；board/q/cursor |
| GET/POST circle/preferences | personalized/interests/mutedCreators/mutedBoards；更新只影响提供的字段 |
| POST circle/reset | 清空兴趣和显式反馈，保留关注与隐藏名单 |
| GET circle/following | 仅本人可读的作者、话题订阅及通知设置 |
| POST circle/follow-creator | username/enabled/notify（默认 false） |
| POST circle/follow-board | board/enabled/notify（默认 false） |
| POST circle/posts/{id}/like | enabled；同人重复操作幂等，禁止自赞 |
| POST circle/posts/{id}/feedback | action=useful/not-interested/clear |
| POST circle/posts/{id}/select | staff；revision/enabled/reason/sourceChecked，不能评选自己 |

data 示例（标题、正文须由用户确认；rightsConfirmed 不自动勾选）：

    {
      "title": "我的机器人项目进展",
      "body": "本周完成了底盘装配，正在找懂控制的同学一起调试。",
      "tags": ["机器人", "控制"],
      "uploads": [],
      "related": [],
      "rightsConfirmed": true,
      "circle": {"format": "moment", "board": "makers", "campus": "shahe", "visibility": "public"}
    }

阅读卡用 format=link，circle.external={platform:"zhihu",url,author,reason,audience}；url 必须是 HTTPS 知乎问题、回答或专栏规范地址，禁止上传附件。服务器补 mode=link-only；用户不能自己填“已精选”或核对时间。

修改/提交/审核/回复/举报/收藏仍走 entries/{id}/...，不要另建平行状态机。校圈首次公开时间由服务端写入 circle.publishedAt，编辑不刷新排序时间。公开卡追加 likes/liked/replies/photos/selection/recommendationReasons/contentType，完整正文仍在 data。

客户端：circleCapabilities/circleBoards/saveCircleBoard/circleFeed/circlePost/createCirclePost/circlePreferences/saveCirclePreferences/resetCircleRecommendations/circleFollowing/followCreator/followBoard/likeCirclePost/circleFeedback/selectCirclePost。

## 验收

专项测试 campus/hub/test_circle.py 覆盖 9 组：真实审核、权限/CSRF、去重点赞、版本与贡献、订阅通知及取消、推荐偏好/重置、知乎链接/精选/重复、游标隔离/撤回、照片 EXIF 与原件、主题管理及探索。

campus/tests/circle_browser_smoke.py 使用临时数据库和 17990/17991，通过 Edge 执行实际 hub-client 的登录→关注→投稿→审核→通知→点赞→反馈→关闭个性化→撤回。它不创建产品页面，页面接入与手机体验仍由 Opus 实现后另验。

运行前迁移，并执行 manage_hub.py hub_import_boards。真实社区没有自动生成帖子或热度；空话题应清楚显示尚无投稿。

本轮最终结果：46 项 Hub 测试、校圈 Edge 客户端流程、全站构建及内容校验均通过。真实本机同源接口确认 6 个空话题、0 条动态，原视频编码能力可用。迁移 0007 已应用；未公开部署。
