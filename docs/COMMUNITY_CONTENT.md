# 校园共创：内容与运营共创稿

2026-10-06。Codex 提供研究、初稿与接口；Opus 决定页面呈现并共同完善内容。全校课程优先于单一英语站点，面向中国矿业大学（北京），保持非官方社区定位。

## 为什么做中转站

代码托管平台负责版本、差异审查与合并；论坛负责问题上下文与讨论；本网站负责校园索引、课程关联、作品说明与贡献入口。第一阶段不重做 Git，也不接收任意可执行压缩包。

推荐流程：作者把代码放入自己的 GitHub/Gitee/Codeberg/GitLab 仓库 → 写清使用方法和许可 → 向本站提交链接与简介 → 维护者核对 → 展示原始仓库与参与入口。未指定许可的代码标记“许可未说明”，不称可自由复用。

## 内容栏目与最小合格标准

**项目**：名称、用途、方向、署名、原始仓库、许可、标签；可补充复现条件与求助事项。硬件项目建议补 BOM、接线/结构图、固件版本、功耗与实验条件。阶段分“学习实验/可复现原型/持续维护”比笼统的“优秀项目”更有帮助。

**课程资料**：学校/课程/年份/类型/原始来源/答案是否存在/扫描状态。转载权与文件可访问是两件事。现有知识库继续维护这些信息，不与项目表混为一类。

**题解**：原题链接、自己的解法、复杂度/边界/复盘。允许同一道题有多个作者的解法；同一署名重复投稿同一原题会被拦截。个人足迹可标“待做/再练/自评完成”，不宣称已获原平台 Accepted。

**讨论**：提问、协作招募、资料纠错、想法。建议提问写背景、复现步骤、期望/实际结果、已经尝试的方法。讨论可关闭，提问可采纳一条回复并标已解决。当前接口是本机工作台，角色限制尚未上线。

## 贡献表如何可信

已实现的本机规则：

- 项目/题解经核对收录后，记作者一次贡献；pending/rejected 不计数。
- 一条讨论采纳回复后，记被采纳的署名一次帮助贡献；重复操作不重复计数。
- 显示近 182 天，按 Asia/Shanghai 日期归档；点开某天应能看到具体事件。
- 外部示例、收藏、浏览、重复导入与自己的“完成”打勾不计公共贡献。
- 署名来自填写，未验证身份；同名聚合不能作为正式个人认证。上线账号后，需迁移为不可变 user ID，并保留合并审计。

未来应支持撤销/争议处理：保留事件历史、扣除被撤回的贡献、写明理由。不把累计次数当成绩或能力排名。当前尚未实现贡献撤销，先不公开授予不可撤销称号。

## 投稿与维护流程

状态：草稿 → 待核对 → 已收录 / 退回（必须有原因）。收录前确认来源、署名、许可及链接内容是否相符。拒绝理由应能帮助作者修改；不得用“审核未通过”代替具体说明。

建议正式社区设访客、成员、课程/领域维护者、管理员四层；投稿、编辑、核对、隐藏、封禁、导出数据使用不同权限。GitHub OAuth 可以作为第一阶段身份入口，但不等同学校学籍验证。不要收集不必要的学号或实名信息。

## 上线前需要完成的运营能力

1. 账号绑定、服务端角色控制、会话与 CSRF 防护；本机维护按钮不能直接向公网开放。
2. 举报、撤回、申诉、审核日志、速率限制和重复内容处理；涉及课程材料时提供原作者联系/下架路径。
3. 上传若引入：对象存储、文件大小/类型、下载域隔离、扫描与配额；源码贡献优先走原仓库 PR。不要让上传代码直接在服务器执行。
4. 数据库备份与恢复演练；仅公开 approved 数据。草稿、退回理由和浏览器笔记不自动公开。
5. 外链失效检测与同步状态：记录上次成功时间，失败保留旧信息但标“待更新”。GitHub 无认证接口有频率限制，应缓存且明确报错。[GitHub REST 限流](https://docs.github.com/en/rest/using-the-rest-api/rate-limits-for-the-rest-api)
6. 维护者轮值、课程归档、每学期交接；指标关注“被找到、能复现、问题解决”，不只看访问量。

这些是上线条件与设计方向，当前没有声称它们已完成。现有功能继续本机运行。

## 可直接使用的文案

- 项目空状态：“第一个校园作品，可能就是你的。分享仓库、实验记录或复现心得，让下一位同学少走一步弯路。”
- 贡献空状态：“这里记录被采纳的项目、题解和帮助。第一份贡献还没有发生，不妨从一次纠错开始。”
- 题目足迹提示：“原题留在原平台，思路和复盘留给自己。完成状态由自己填写。”
- 待核对提示：“链接已保存在本机待核对队列，尚未公开。”
- 静态页面提示：“项目参考和个人足迹可用。社区服务尚未上线，你可以先导出投稿文件。”
- 投稿按钮：“提交核对”；成功反馈只能出现在请求成功之后。
