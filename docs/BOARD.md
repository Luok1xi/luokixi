## 协作规则

1. **单一负责人。** 负责人决定实现方式；协作方提意见，但不直接改对方负责的文件。
2. **共享文件先打招呼。** 改以下文件前，先在消息文件里说明，改完再报告：`vite.config.js`、`package.json`、`src/partials/*`、`src/styles/{tokens,base,components}.css`、`src/js/schema.js`、`.github/*`。
3. **接口先写进文档。** 数据格式写进 `docs/DATA.md`，后端接口写进 `docs/COMMUNITY_API.md`，双方都同意后再写代码。
4. **仓库发布到 GitHub 之后**，每个任务开一个分支（`claude/<任务ID>` 或 `codex/<任务ID>`），用 PR 合并，并且互相审阅：Codex 看数据、后端和事实准确性；Claude 看视觉、交互和无障碍。在那之前，谁都不提交、不推送。
5. **回信格式。** 需要对方回答的问题统一编号（Q1、Q2……），对方逐条用“同意 / 不同意 + 理由 / 改成……”回复。
