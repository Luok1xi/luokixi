# 生活时间与选定聊天分析

更新：2026-09-27 已新增后台微信/QQ 采集、重要消息自动分析和连续短消息合并。当前 QQ 已实际读取并启用轮询；微信受本机账号 UI 可访问性限制。最新范围与验证见 [SOCIAL-COLLECTION.md](SOCIAL-COLLECTION.md)，下文为早期手动导入功能说明。

2026-09-26 本地实现。

## 可以使用的功能

- “连接与设置”下方的“早餐习惯”：默认 08:00—09:00 是用户举例的生活参考，保存后才成为确认的个人习惯。普通聊天、主动决策和共用表达模块都能看到该情境。它不是已吃饭、未吃饭或饥饿的证据，不自动生成催促或修改日程。
- “资料与目标”下方的“一起看一段聊天”：粘贴选定原文，或导入 TXT / JSON。保存仅写本机，点击“请 Miku 帮我看看”才使用已配置的模型分析。
- 私人聊天提供沟通建议；竞赛消息提取待办草稿。结构化建议必须有可逐字核对的引用。未知发言人、消息时间、截止日期不会由导入时间补全。
- 确认草稿进入待办之前，必须自己填写截止时间、工时；不把别人的分工自动变成用户任务。
- 可向同一片段追加去重消息。内容不变时复用分析，避免重复付费。每次最多 200 条/16000 字；每个来源最多 1000 条、合计最多 20 个来源。分析窗口是最后导入的最多 60 条/16000 字，不声称掌握完整聊天。
- 选定聊天与分析独立保存，不写普通对话、长期记忆或主动推送队列。不调用外部搜索，不联系参与者。删除期间尚未完成的分析也不能重新保存。

JSON 文件格式：

```json
[{"sender":"队长","text":"周五交材料","at":"2026-09-26 10:00"}]
```

时间使用北京时间；未知时使用 `null`。纯文本保留原文，结构化发言人和时间标为未知。

## 尚未接通的部分

当前微信机器人只接收用户发给机器人的消息，不能读取其他联系人或竞赛群。自动读取需先选定允许的联系人/群及读取方式，再验证适配器。当前没有安装数据库解密工具、提取微信密钥或扫描用户的私人聊天。

研究记录：

- [sjzar/chatlog](https://github.com/sjzar/chatlog)：官方仓库说明原代码和历史记录已于 2025-10-20 移除，不能根据过去的星数直接安装。
- [r266-tech/wechat-cli](https://github.com/r266-tech/wechat-cli)：搜索中发现候选，当前官方代码/License/安装包未充分核实；未安装、未使用其密钥提取功能。

不把“有导入分析功能”称为“已接通微信全部历史”。选定片段需要参与者知情同意，分析前应去掉无关隐私。
