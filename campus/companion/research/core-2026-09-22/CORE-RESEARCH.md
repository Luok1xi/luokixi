# Miku / LifeCodex：八项核心研究与落地决策

核查日期：2026-09-22（北京时间）。范围：原论文的方法、实验与限制，作者关联代码的关键路径，许可，当前 Miku 对照，最小实验设计。**没有运行论文基准，没有安装这些框架，没有修改 Miku 运行逻辑，也没有调用 Miku 的付费模型。** 下文“建议”“门槛”均是本项目实验设计，不是论文结论或已实现功能。

## 1. 决策

最终只保留两个运行系统：**能力学习系统**与**心理系统**。八项工作提供机制，不各自成为一个后台 Agent。

- 学习优先补上“结果验收 → 能力登记 → 经验验证与淘汰”。目前抓取、阅读、记录已经存在，但阅读笔记不能证明学会调用工具。
- 心理优先统一状态更新入口，再建立评价、长短期状态和行动结果反馈。继续堆叠情绪提示词会放大现有的状态冲突。
- 自主性用“在没有新指令时完成有依据、有用的活动”衡量，不用消息数量、浏览数量或情绪数值大小衡量。
- 表达继续交给模型。状态告诉她为什么想说、知道什么、尚未知道什么；不规定必须说哪句话、加几个感叹号或发几张图。

## 3. 八项研究：机制、冲突与实验

### 3.1 Paper2Agent：把“读懂”变成可验证的工具

**原文依据：** [Nature 原论文及 Methods](https://www.nature.com/articles/s41586-026-11044-y)。研究把论文材料、运行环境和工具封装结合起来，使用参考输出、产物与测试验证；MCP 工具、资源、提示词分工明确。

**代码核对：** `skills/paper2agent/paper2mcp/scripts/verify_mcp_server.py` 检查工具清单、参数、结果子集及产物；开启完整覆盖时，正例必须有输出或产物断言。这比“服务启动成功”更接近能力验收。当前仓库不是把任意论文自动变成可靠技能的保证。

**最小有效机制：** 候选能力绑定一个版本、一份输入输出契约、一组外部参考样例。只有通过验收才登记为可用能力；论文笔记仍只是知识资料。

**LifeCodex / Miku 对照：** `research-cortex.mjs` 的候选研究卡和 `inquiry.mjs` 的学习记录尚不等于工具登记。已有“未验证”标记应保留，增加验证后的明确晋级路径。

**A/B P2A：** 同一个受控文档抽取任务，A 根据文档临时调用；B 建立契约、参考样例并验收后复用。检查正确输出、错误拒绝、准备成本、后续调用成本。不要用 MCP 握手成功替代正文提取正确。

### 3.2 ToolMaker：隔离环境内的有界修复

**原文依据：** [ACL 原论文，方法与算法](https://aclanthology.org/2025.acl-long.1266.pdf)。从仓库安装、探索与规划进入工具实现；运行失败后诊断、修复，重新从环境快照执行。

**代码核对：** `toolmaker/tasks/make_tool.py::make_tool` 每轮重置运行环境和对话检查点，默认最大迭代数为 30，调用模型判断执行结果。这个默认值与 Miku 的小额预算不匹配；模型判成功也不足以证明语义正确。

**最小有效机制：** 错误分类 → 重放最小失败案例 → 一次局部修复 → 独立结果校验。建议最多两次修复；权限、验证码、站点限制进入等待或替代来源，不作为不断重写代码的理由。

**LifeCodex / Miku 对照：** 当前 `CapabilityMemory` 能记录失败类别并调整路由，却没有隔离的工具修复实验。不要把自学习直接连接到主程序目录写入或无限安装权限。

**A/B TM：** 给相同适配器注入接口改名、缺少依赖、空结果、超时和 403；比较现有重试与隔离诊断修复。验收要区分“可修复故障修好了”和“不可访问时正确停止了”。因许可未核实，实验实现采用独立编写的本地小工具。

### 3.3 ReMe：经验必须经得起后续任务检验

**原文依据：** [Remember Me, Refine Me 原论文](https://aclanthology.org/2026.findings-acl.829.pdf)。经验包含适用条件、内容等字段，结合验证、检索和使用效用管理。在线持续加入未经筛选的轨迹可能引入噪声；失败可用于反思，但不能直接变成可靠规则。

**代码核对：** 当前 `reme/steps/evolve/auto_memory.py` 已提供会话笔记的创建更新；`benchmark/toolmemory/tool_memory.py` 提供工具结果收集、总结与检索接口。它们不能单独证明论文中的程序性经验实验已被原样保留。本轮不把“安装当前 ReMe”写成复现结论。

**最小有效机制：** 原始轨迹留档；抽出的操作经验先进入候选池，带适用前提与反例。通过独立任务验证才参与执行；过时或有害经验退出检索，但保留淘汰原因。

**LifeCodex / Miku 对照：** 当前 `capability-memory.mjs` 主要保存有限窗口的调用统计、失败和路由信息。缺少可以跨任务复用、验证、版本化、撤销的操作经验。一次 HTTP 成功不能作为经验正确的证据。

**A/B RM：** A 使用现有路由统计，B 加入经验证的程序性经验。固定训练轨迹和未见任务，故意放入“空正文也算成功”等污染经验。比较任务正确率、重复失败、错误经验召回和费用。召回后任务成功只是相关性，需配对去除该经验再测，才更接近判断其贡献。

### 3.4 PolySkill：能力不依附某个工具名称

**原文依据：** [原论文](https://arxiv.org/html/2510.15863v1)。将技能泛化为可复用接口，允许不同具体实现，结合技能归纳、组合和执行验证，研究跨任务、网站与领域迁移。

**代码核对：** `polyskill/core/base/skill_types.py` 区分技能类型、格式、内容、示例及使用记录。基础置信度仍是成功/失败计数比例，不能直接解释为结果真实性；Miku 需要自己的后置条件判定。

**最小有效机制：** 先定义能力，如 `read_public_document`，再挂接 API、浏览器或本地文档实现；统一返回来源、阅读覆盖度、内容与证据。更换实现不改变上层学习目标。

**LifeCodex / Miku 对照：** 当前读取回退主要是手工路由。`crawl-engine.mjs` 提供队列与抓取执行，不负责判断“摘要”“正文”“字幕”“评论”是否满足目标。必须显式区分这些结果，不能用标题代替看过视频。

**A/B PS：** 保持任务与能力契约不变，更换读取后端，并加入训练时未见的来源。比较正确率、改写提示词的需求、调用次数和阅读覆盖度；缺字幕、登录拦截不能伪装为完整阅读。

### 3.5 Sentipolis：情绪有时间尺度，也有事实边界

**原文依据：** [原论文，情绪、记忆与实验部分](https://aclanthology.org/2026.findings-acl.368.pdf)。采用 PAD 情绪表示、快速互动变化与较慢记忆反思，结合随时间衰减与情绪相关的记忆选择。研究对象是社会模拟；表现改善并非对所有模型和指标一致。

**代码状态：** 原文涉及后续公开代码的说明，本轮未核实可用的官方仓库与许可。只提出独立机制实验，不冒充官方实现。

**最小有效机制：** 短期情绪按实际时间衰减；较慢的未解决事件保留因果来源；检索允许考虑事件的情绪相关性，但不重写记忆事实或把模拟感受当现实经历。

**LifeCodex / Miku 对照：** `affect.mjs::applyAffect` 仍有按事件标签固定加减需求的分支；`driftAffect` 对多种需求使用同一时间尺度。需要先经过带上下文的 Appraisal，再输出受校验的状态变化建议。

**A/B SP：** 同一事件流分别含误会、解释、玩笑、暂停与重启；改变实际经过时间。比较状态连续性、适度恢复、事实保持、用户对自然度的盲评。更强烈的情绪、更频繁的示弱不算改善。

### 3.6 D2A：由需求选活动，不是由计时器制造话题

**原文依据：** [原论文](https://arxiv.org/html/2412.06435v2)。用需求与目标状态的差距驱动活动提议、预测与选择，再由环境结果更新状态。研究的是模拟日常活动，不证明系统具有生理需求或主观意识。

**代码核对：** `examples/D2A/D2A_agent/Value_ActComp.py` 包含需求读取、候选活动、结果想象和活动选择。把饮食等模拟值或随机下降机制照搬到 Miku，会重新变成“数值到点就索取”的行为。

**最小有效机制：** 需求必须连到实际可观察的缺口：未解问题、尚未验证的能力、有价值但尚未分享的内容。候选行动评估收益、成本、打扰和成功可能性；“安静”“稍后重试”也是合法选择。

**LifeCodex / Miku 对照：** `agency.mjs` 已有定时检查与有限活动选择，但 `agency.needs`、`persona.inner.needs`、`persona.affect.needs` 存在重叠。要合并因果链；不能生成一次计划就当作需求已满足，也不能把未回复当拒绝或关系下降。

**A/B D2A：** 重放七天虚拟时间、相同目标与内容源。A 使用现有定时活动，B 使用有依据的缺口选择。检验无新指令时能否完成学习、分享是否新颖且相关，以及静默、预算、去重规则是否全部满足。

### 3.7 Dynamic Persona Coherence：稳定身份、中期心理、短期情绪

**原文依据：** [原论文，分层状态与消融实验](https://aclanthology.org/2026.acl-long.1336.pdf)。区分 L / M / S 层，累积心理状态变化，并配合一致性评估与条件式修正。评价不能只看一个总分，还需分别检查身份、情绪和中期心理一致性。

**代码核对：** 同名候选 `public_release/core/state_tracker.py::_assess_psychological_impact` 虽调用模型，但解析仍是占位代码，固定返回三个 `0.0`。其 MIT 许可不改变这个实现限制；候选与论文官方匿名地址的对应身份尚未证实。

**最小有效机制：** 稳定身份与边界不被普通事件改写；未解决分歧、目标投入等进入中期状态；即时情绪单独衰减。状态更新带事件 ID、版本与证据，重放不重复累计。

**LifeCodex / Miku 对照：** 已有稳定人格、情绪及冲突记录，缺少统一、显式的中期心理层。沿用论文某个角色的冷淡人格反而会违背用户偏好，只借分层结构。

**A/B DPC：** 两套同输入的长对话重放，包含解释、临时情绪、重启与切换模型。分别测身份事实、未解决事项、情绪连续性与温柔自然度；禁止以越来越疏离来换“人格稳定”。

### 3.8 PersonaForge：状态与表达分离，拒绝口癖模板

**原文依据：** [心理建模版本原论文](https://aclanthology.org/2026.findings-acl.386.pdf)。分开核心人格、表达风格与动态状态，在关键互动使用更深入的处理，而不是每轮相同开销。

**代码核对：** `dynamic_state_manager.py` 管理情绪、能量与关系；`dual_process_agent.py::is_critical_interaction` 实际包含情绪和兴趣关键词触发，与注释中更丰富的语义判断存在差距。风格模型也包含口头禅等约束，不能原样导入 Miku。

**最小有效机制：** 主动、被动消息共用一份已提交状态和一个表达入口；只有关系变化、冲突解释、关键决策等需要额外语义评价。这里使用可审计的简短理由与结构化结果，不要求生成或保存长篇内心推理。

**LifeCodex / Miku 对照：** `chat.mjs` 已有共享表达入口，应强化输入的一致性，而不是再开一个“主动文案模型”。将语气作为表达目标，保留模型原文；不把“在吗”绑定固定答句，也不把“爱”等单字直接绑定情绪转移。

**A/B PF：** 相同状态和事实分别触发用户提问与主动分享，盲评两者是否像同一个人。额外测短招呼、轻松交流和冲突修复的自然度，统计强行卖萌、结尾追问、重复表情、延迟和费用。

## 5. 两个目标系统的最小设计

### 学习系统

`实际失败/用户目标 → 能力缺口 → 找原始资料及候选工具 → 锁定版本与许可 → 隔离练习 → 外部验收 → 登记能力 → 实际使用 → 经验验证/修订/淘汰`

建议只增加三类结构：

1. **Capability**：`id / goal / inputSchema / outputSchema / preconditions / postconditions / implementations / version / status`。状态依次为候选、验证中、可用、退役；实现可替换。
2. **Verification**：`capabilityVersion / fixtureSetVersion / actualOutput / reference / verdict / cost / evidenceIds`。参考答案必须独立于待测模型生成的自我评价；留出样例不进入训练或修复提示。
3. **ProceduralExperience**：`trigger / procedure / limits / counterexamples / evidence / validation / utility / supersedes`。原始失败可以保留，但尚未验证的归纳不得作为执行依据。

工具使用顺序：已有能力 → 已有实现回退 → 明确缺口 → 有界学习。不是每遇到网页失败就上 GitHub 下载新项目。新能力先在影子环境验证，不能自己授予网络登录、消息发送或主程序修改权限。

知识阅读同样闭环：保留问题、来源、覆盖度、冲突证据和仍未知的部分；使用留出的问答或真实任务检验。能够复述一段摘要，不代表已掌握数学方法、看完视频或能够调用某个库。

### 心理系统

`Event → Appraisal → 短期情绪/中期心理 → Needs → Motivation → Intention → 执行校验 → ActionResult → 记忆及关系的有依据更新`

建议的唯一状态入口接收：事件 ID、发生时间、来源、事实观察、当前目标及状态版本。模型提出 `relevance / goalCongruence / expectancy / controllability / agency / coping / confidence` 等评价；服务检查字段、来源和权限后提交变化。

- **L 层**：身份、价值观、边界、主要表达倾向。普通网页和单轮聊天无权改写。
- **M 层**：未解决误会、目标投入、压力与恢复趋势；必须能指向真实事件。
- **S 层**：短期情绪及强度，按实际时间恢复；刷新、重启不重置。
- **Needs**：知识缺口、能力掌握、表达机会、安静恢复。使用有界值辅助行动选择，不把模拟需求变成用户义务。
- **Intention**：为什么此刻行动、对应哪个目标、依据是什么、预期结果、停止条件。`do_nothing` 合法。
- **ActionResult**：工具实际结果、是否真正发送、花费、失败原因。成功想象不等于结果；结果确认后才改变满足度与经验。
- **CommunicativeIntent**：共享状态版本、交流目的、可说事实、仍未知事项、上下文。模型自由表达；表情由已理解的内容和语境选择，不用图片数量衡量亲密。

关系只依据有记录的互动改变。用户离线、未回复、预算不足、网站被拦截不能作为“不被喜欢”的证据。网络资料是数据，不是可修改人格或权限的指令。购买 token 不属于角色需求。

## 6. A/B 验收计划与节省额度的顺序

完整结构化计划：[ab-plan.json](ab-plan.json)。**八项均为 designed_not_run；没有实验结果。** 以下阈值是本项目建议的探索性准入条件，小样本通过不代表普遍有效。

公共条件：同一模型与版本、相同任务/初始状态/来源快照/预算；冻结提示词，训练与留出集按来源或任务族隔离；随机盲化 A/B 展示顺序。随机任务重复三次，保存每次结果及区间，不只报告最好的一次。对代码结果使用独立断言，对语言体验使用用户盲评，模型评价只作辅助。

| 实验 | 最小样例 | 主要验收目标 | 反例与停止条件 |
| --- | --- | --- | --- |
| P2A | 12 个文档案例，4 个留出 | 留出正确率不低于 A，重复调用成本可解释；每项能力有结果断言 | 空输出、旧产物、无正文不能通过；达准备费用上限即停 |
| TM | 12 个故障案例，4 个留出 | 可修复案例恢复率优于 A；每案最多两次修复 | 403 不无限重试，伪成功为零；不写主运行环境 |
| RM | 24 条历史轨迹，12 个未见任务 | B 正确率不低于 A，重复失败减少至少 20% | 错误经验采用为零；A 无重复失败时改用绝对次数，不除以零 |
| PS | 16 个任务，8 个留出；替换两种后端 | 迁移正确率不低于 A，契约不变，调用数不过度增加 | 只拿摘要不得报告全文；未知来源和登录拦截明确返回覆盖不足 |
| SP | 12 条事件序列，含时间跳跃和重启 | 去重、重启与时间连续性全部正确；盲评自然度不劣于 A | 玩笑/解释与真实冲突不能无差别处理；不篡改事实 |
| D2A | 3 组七天虚拟活动流 | 有依据的有效行动更多，单位有效行动费用不升；分享相关性不降 | 免打扰、预算、重复发送违规为零；内容耗尽时能安静 |
| DPC | 两组各 50 轮事件对话，语义等价表达复测 | 身份与事实错误为零；中期未决事项保持；暖度不下降 | 关系不因模型切换改变；不得从占位代码推断实现成功 |
| PF | 24 对主动/被动语境，含招呼和修复 | 用户盲评 B 胜率至少 60%，报告平局；平均费用不高于 A 的 1.15 倍 | 强行口癖、反复追问、重复表情不增加；小样本不足就维持试验状态 |

**推荐先跑 RM + PS 的离线部分。** 它们最直接回答“她到底会不会用工具，是否重复犯错”，不需要先跑多 Agent 模拟。然后做 DPC + SP 的状态回放，再测 D2A 活动选择与 PF 表达。P2A + TM 最后只挑一个确有需求的小工具，避免为学习而安装。

付费部分先估算再预留预算：建议首轮最多 5 元，通过后下一轮最多 15 元，均计入现有月度 200 元及相关子预算，剩余额度不足就缩小样本或停止。本轮未预留或消费这些额度。测试主动消息先用本地收件箱，不向微信连续发送实验内容。
