# 通用信息查询

## 1. 先把问题拆清楚（不调用工具）
- 写下要回答的核心问题，以及回答需要的 1—3 个具体事实（例：「XX 报名截止日期」「YY 的官方价格」）。
- 判断信息类型，决定第一选择的来源：
  - 定义、背景、人物、作品 → wiki_search（中文话题同时查 en，英文条目通常更全）
  - 规则、政策、价格、产品参数、活动安排 → web_search 并优先官方站点（site 限定 gov.cn / edu.cn / 品牌官网）
  - 操作经验、踩坑、评价 → web_search + community_search（zhihu / bilibili），注意这是个人经验
  - 编程或数理问题 → 改用 tech-research 技能

## 2. 第一轮检索（并行）
- 同一轮发出 2 个互补查询，例如：
  - 中文查询 + 英文查询；或
  - 「实体 + 具体属性」+「实体 + 官方/公告」
- 检索词写实体全名和限定词，不写整句问题；避免「最好的」「推荐」这类空泛词，改成具体指标。
- 有时效要求时设置 freshness（week / month / year）。

## 3. 筛选与精读
- 从结果里挑 2—3 个最可能包含答案的来源：官方 > 权威媒体/百科 > 专业社区 > 个人博客/营销页。
- 用 read_page 读原文，focus 写成要找的具体事实（如「报名截止时间和报名方式」）。
- 摘要与原文不一致时，以原文为准；原文日期过旧要注明。

## 4. 不够就调整，不要重复
- 结果不相关：换同义词、换语言、加 site 或时间限定，或换工具（wiki / community / qa）。
- 两轮后仍找不到关键事实：停止，在 gaps 里写清楚缺什么、可能在哪里能找到。

## 5. 提交
- answer：先给直接结论，再补充条件和例外，每个事实后标来源编号。
- findings：每条一个事实 + 来源编号 + 原文逐字片段。
- 多个来源说法不同：都列出并说明哪个更可信、为什么。
